# Corresync 0.9.3

## What's Changed

- Outlook Web draft/send accepts attachments up to **20 MiB per file and in
  total**, with up to 10 files. CLI and MCP use the same approval-bound payload.
- Approval and daemon transport bounds accommodate Base64 attachments and
  worst-case JSON escaping of valid bodies. Pending approvals retain a combined
  512 MiB payload budget plus existing expiry and count limits.
- Cross-account mail, task, and agenda pagination can reach the entire existing
  bounded workset instead of stopping at offset 400. Per-source limits remain.

- Preview tracking now labels a selected stable release correctly and explains
  when no newer preview was found. Stable updates retain package-manager
  upgrade guidance even while tracking preview.

## Limits and validation

This expansion applies to **Outlook Web**. Graph, Gmail API, IMAP/SMTP, and JMAP
retain 2 MiB per file and 3 MiB total; larger inputs fail before remote draft
creation or upload. Provider and tenant limits may be lower than Corresync's
limit and include message encoding overhead. No new live-provider compatibility
is claimed: large uploads are covered by synthetic contract tests.

Attachment download bounds remain unchanged: Outlook Web CLI file downloads
allow 30 MiB; inline MCP and other mail routes allow 2 MiB. Calendar queries
remain bounded to 31 days, and per-page sizes remain bounded.

Configuration schema v12 is unchanged. Private daemon protocol v29 replaces
the earlier owner through the authenticated lifecycle. Standalone users can
run `corr update`; package-manager users should use their manager's upgrade.
Restart connected MCP hosts to load the current CLI.

The shared REST request ceiling is 12 MiB so existing small-mail inputs fit
after MIME, quoted-printable, and Base64 expansion. This does not increase
other providers' attachment input limits or their response limits.
