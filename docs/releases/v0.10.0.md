# Corresync 0.10.0

## A plainer command line

Help, prompts, output, and errors were rewritten so they say what a command
does in ordinary words. Nothing a script depends on changed: command names,
flags, defaults, JSON output, exit statuses, and the configuration schema are
the same.

- `corr --help` groups commands: everyday (mail, calendar, agenda, tasks,
  queries), accounts and sign-in, AI agents, maintenance, and advanced.
- Each command group explains once how changes work (a preview first, then the
  same command with `--approve`) and where message IDs and change keys come
  from, and gives examples you can paste. Every example is checked by a test.
- Previews use labelled lines and end with the exact command that carries them
  out. Empty results say what was searched.
- Errors say what happened and, where there is one, the next command to run
  (`Try: corr auth login --account work`). Causes that used to be replaced by a
  fixed sentence are shown. A browser that cannot start is reported in one line
  instead of Chromium's crash output.
- A test walks every command's help and fails on internal vocabulary, so the
  wording does not drift back. The rules are in CONTRIBUTING.

## Setup and settings

`corr setup` now asks for your email address first. Tab completion and
connecting AI agents come after the first account. When the address gives no
way to connect, the wizard offers the manual choices (IMAP/SMTP, JMAP, CalDAV,
Outlook Web, Microsoft Graph, Google with your own OAuth client) instead of
stopping. When a connection needs something you must prepare, such as your own
Microsoft app registration, it says what that is, links the guide, and offers
another way. Answered prompts leave a one-line record. The summary names the
settings file once and ends with the next command.

`corr settings` clears a cancelled prompt before the next screen, wraps text
without splitting addresses, and has one "Sign in" entry that does the right
thing for the computer it runs on.

Running `corr setup ADDRESS` from a script, with or without `--json`, behaves
as before.

## Sign-in requested by an AI agent

Until now an MCP client could never start a sign-in. With the new
`account_sign_in` tool an agent can ask for one. Your MCP client then asks you,
with text Corresync writes itself: the account, its address, and the page the
sign-in will open. Only if you accept does Corresync start the same sign-in as
`corr auth login`. You type passwords, MFA codes, and consent in the browser;
none of it passes through the agent.

Limits, on purpose:

- It works only for an account that has already completed a sign-in you started
  from the terminal, with the same connection settings. After an account is
  added or its connection changes, sign in once with `corr auth login` first.
  This keeps an agent from pointing a sign-in at a page of its choosing.
- If you decline, or a prompt goes unanswered, the same account is not asked
  again for ten minutes, including across a daemon restart.
- It needs a client that supports MCP elicitation and a computer with a
  display. Otherwise the agent gets the command for you to run, as before.
- Signing out and clearing browser data remain terminal-only.

`corr auth login` itself now prints the account and the page it will sign in
to before anything opens. The first time an account signs in with given
connection settings, and whenever they change, it asks you to confirm that
page on an interactive terminal; the default answer is no. Scripts and
`--json` runs get the notice and continue. With `--host` the notice comes from
the server and there is no question on your own computer.

A client that shows the approval request to the model, or lets the model answer
it, lets the model approve. Corresync cannot detect that. In that case the
limits above still hold: the destination is one you already used, and
credentials are typed by you in the browser. See
[ADR 0039](../adr/0039-user-approved-sign-in-from-mcp.md).

## Login view on hosts without a display

The page that shows a remote sign-in in your own browser now has clear states
(starting, loading, ready, "check the screen", ended) and the time left before
the link expires. It has a Paste button and handles Ctrl+V or ⌘V, relays
pointer movement so hover menus work, refreshes faster while you interact, and
does not resend an unchanged picture. It has a dark mode and fits a narrow
window.

`corr auth status` shows a sign-in that is still in progress, which kind it is,
and when it expires. `corr auth login --host` needs 0.10.0 on both computers.

## Fixes

- OAuth providers (Google, Microsoft Graph, Todoist, TickTick): when a token
  expired during sleep and its refresh was rejected, a write that was never
  sent was reported as "outcome unknown" and the account still showed as signed
  in. It is now reported as not sent, with the sign-in step
  ([#228](https://github.com/nkiyohara/corresync/pull/228)).
- `corr update check` asks the release endpoint each time instead of repeating
  a failed lookup cached for 24 hours, and says why a check failed
  ([#226](https://github.com/nkiyohara/corresync/pull/226)).
- Suggested commands are quoted for PowerShell on Windows.

## Reliability and evidence

- Sleep, network loss, and session expiry are covered by deterministic tests
  for every kind of session: reads recover or report a clear state, writes are
  never sent twice, and one account's failure does not affect another.
- The compatibility tables in `docs/compatibility.md` and `docs/tasks.md` are
  generated from one catalog, and tests compare it with what the code enables.
  This removed a line that called Slack a preview; Slack messaging is off.
- Every shipped route has an opt-in live observation harness or a documented
  manual procedure, and a guard keeps default tests and CI from reaching a real
  account. No new live observation is recorded by this release.
- All Go modules, development tools, and pinned GitHub Actions were updated.

## Compatibility

- Additive JSON: `corr auth status --json` may include `pendingSignIn` per
  account, and the sign-in action object may include `nextAction.mcpTool`.
- The MCP catalog has 72 tools (`account_sign_in` is new).
- The private daemon protocol is 33; the updated command restarts the local
  daemon. The `--host` helper wire is version 2.
- The `corresync` command still ships as a compatibility entry. ADR 0016
  allows removing it from 0.10.0 onward after a stable release announces it;
  this release does not announce a removal.

## Evidence and remaining limits

The new login view, setup, and settings screens were driven in a real terminal
and a real Chromium, and the login view was run on a Linux server without a
display against the real Outlook Web sign-in page up to the point of entering
credentials. A complete sign-in through the view, and the `account_sign_in`
flow in a real MCP client, are not recorded yet; both are covered by synthetic
tests only. Passkeys on your own computer, USB security keys, and client
certificates are still not forwarded by the login view.

## Upgrade

Standalone installations can run `corr update`. Package-manager installations
should use their manager's upgrade command. Restart connected MCP hosts so they
load the updated executable and see the new tool. Configuration schema v12 is
unchanged.
