# Corresync 0.9.5

## Sign-in on hosts without a display

The login view that shows a remote Outlook Web sign-in page in your own
browser (`corr auth login --web` and `--host`) did not work in 0.9.1 through
0.9.4. The daemon answered with a screen frame, and the client only accepted a
text view, so the first response was always rejected. The command hid that
error, and the headless browser stayed open until the login timeout, which also
blocked a retry. The synthetic tests used a stand-in client and did not catch
it.

What changed:

- The client accepts graphical results and checks the frame's size and HTTPS
  origin. A test now sends them through the real client and server.
- On Linux without `DISPLAY` or `WAYLAND_DISPLAY`, a plain
  `corr auth login --account ALIAS` starts the forwarded login view. It prints
  the `ssh -L` command with the host's name and the link to open. `--json`
  still stops with an explanation.
- Enter is sent with its character, so sign-in forms submit.
- A screenshot taken while the page navigates is retried, and each attempt is
  bounded. Chromium does not answer a screenshot request whose page was
  replaced, so a second sign-in on a saved profile used to hang for the whole
  request timeout.
- Tabs that Chromium restores from a profile's previous run are closed at
  launch. They used to pile up on every start.
- A new login for the same account replaces an unfinished one. The earlier
  browser is closed and never reused. SIGHUP cancels the command the way Ctrl-C
  does, so a dropped SSH connection no longer leaves a login behind.
- When a login cannot start, or the remote login is gone, the view ends and the
  terminal prints the reason.
- The `--host` helper also looks for `corr` in `~/.local/bin`, `/usr/local/bin`,
  and the Homebrew directories, because a command run over SSH does not read
  the login profile.

See [signing in on a host without a display](../remote-login.md).

## Draft recipients

Saving a draft now returns an `addressing` object with the To, Cc, and subject
the provider resolved, for new messages, replies, reply-all, and forwards. For a
reply it also counts the people on the original message that the draft leaves
out, and the output says that `reply-all` keeps them. `unresolved` means the
route could not tell; it never means an empty list. Bcc is not reported, and
the original message's Bcc is never requested.

Help for `corr mail draft` and `corr mail send`, the MCP tool descriptions, and
the error for explicit recipients on a reply now name all four modes. The agent
skill tells agents to pick the mode from the intended audience and to check the
resolved recipients before calling a draft ready. This addresses
[#221](https://github.com/nkiyohara/corresync/issues/221).

Outlook Web reads the saved draft back at its exact version. IMAP/SMTP, JMAP,
and the Gmail API report what they composed. Microsoft Graph reports what the
create call returned and does not count omitted participants.

## Dependencies

The compiler is pinned to Go 1.27.4 for GO-2026-6859, a crash in HTTP/1 servers
that use `MaxBytesReader`. gorilla/websocket is pinned to the commit that fixes
GO-2026-6278, a weak random source for the WebSocket mask key. That fix has no
tagged release. Only the Mattermost event stream uses the library.

## Documentation

The README and the website were rewritten in plainer language in English,
Japanese, Korean, Simplified Chinese, and Traditional Chinese. Legal pages are
unchanged. Outdated statements found during the rewrite were corrected,
including the number of MCP tools (71).

## Evidence and remaining limits

The login view is tested in a real Chromium: input, form submission, page
navigation, and a login that ends early. On 2026-11-25 it was run on a Linux
server without a display against the real Outlook Web sign-in page, up to the
point of entering credentials, using a synthetic address. A complete sign-in
through the view, a login started from a Mac, and the Orca workflow are not
recorded yet. Passkeys on your own computer, USB security keys, and client
certificates are still not forwarded. Teams Web is not covered.

Draft addressing has synthetic coverage for every route and no live
observation. The count of omitted participants compares addresses as text, so
an alias of your own account can be counted.

No provider capability, consent step, or preview gate is widened by this
release.

## Upgrade

Standalone installations can run `corr update`. Package-manager installations
should use their manager's upgrade command. Restart connected MCP hosts so they
load the updated executable. For `corr auth login --host`, install 0.9.5 on both
computers. Configuration schema v12 is unchanged. The private daemon protocol
is now v30; the updated command restarts the local daemon.
