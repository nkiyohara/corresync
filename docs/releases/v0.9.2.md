# Corresync 0.9.2

## What's Changed

- **Verified automatic updates by default for new standalone configurations.**
  Interactive starts, including bare `corr`, use the existing 24-hour-cached
  release check. Installation verifies Sigstore provenance, SHA-256, version,
  and platform and keeps a rollback copy. Existing configuration preferences
  remain unchanged, including an omitted or explicit `auto_install = false`.
- **Update the running session owner as well as the executable.** After
  verification, stop the authenticated config-scoped owner, confirm it has
  stopped, install, and restart it from the updated path. A busy owner defers
  replacement. The requested command then runs once in the updated executable.
- **Retire obsolete daemon images.** Daemons from 0.9.2 detect replacement of
  their original executable and retire after admitted operations finish,
  including owners using other configuration files. Their next provider command
  starts the current owner. Older CLI images cannot replace a newer owner.
- **Keep package-manager ownership.** Homebrew, Scoop, WinGet, and system
  packages continue to show their manager's upgrade command; automatic updates
  never overwrite those packages or run a package manager.

- **Surface browser authorization observation failures (#202).** Terminal and
  graphical login now report exact-origin or unsupported-authorization errors
  instead of remaining pending. The configured exact-origin boundary remains
  unchanged; the mailbox page URL alone does not establish the failing cause.
- **Explicit saved-browser sign-out (#202).** Normal logout keeps browser
  sign-in. `corr auth logout --account work --clear-browser` also removes that
  account's dedicated Outlook/Teams browser storage after closing its sessions.
  Other accounts and OS credentials remain; OS/provider SSO may still sign in.

## Upgrade notes

For an existing standalone configuration, enable automatic installation with
`corr config set updates.auto_install true`. Disable it with
`corr config set updates.auto_install false`. MCP, daemon, configuration,
completion, JSON, piped, and non-interactive commands never trigger installation.
`CORRESYNC_NO_UPDATE_CHECK=1` disables startup checking and installation.

The coordinated update behavior applies to updates performed by 0.9.2 and
later. Pre-0.9.2 processes retain their earlier lifecycle behavior until
replaced. After this upgrade, restart connected MCP hosts and run
`corr daemon start` to replace an older session owner. Restarting never starts
provider authentication automatically; sign in explicitly if needed.
Configuration schema v12 is unchanged. Private daemon protocol v28 replaces
the earlier owner through the authenticated lifecycle.

Teams Graph, Teams Web, Mattermost, and real Mac-to-Linux graphical provider
login retain the live-verification limitations documented for 0.9.1.
This release adds synthetic lifecycle tests; it does not claim new live-provider
verification.
