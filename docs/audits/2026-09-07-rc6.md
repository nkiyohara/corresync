# RC.6 code audit

Date: 2026-09-07. Baseline: `e59d3944c38cfbda67d130c03203e6c13c4754ad`
(`v0.9.0-rc.5`). The candidate includes the resulting corrections and their
synthetic regressions.

## Coverage and method

Eleven Codex reviewers divided the first-party implementation by ownership.
A separate inventory reconciliation accounted for 288 production Go files in
64 directories and 78 non-Go executable/build/configuration paths, with no
unassigned file in that inventory. New implementation files were included in
the subsequent integration reviews. Dependencies were checked through their
pinned contracts, license checks, and vulnerability scanning; this was not a
manual audit of every vendored dependency line.

Reviewers proposed patches outside the working tree. The primary reproduced
findings against the current code, inspected the implementation and relevant
provider contracts, applied accepted changes, and ran integrated checks.
Independent follow-up reviews crossed the original ownership boundaries.
Several proposal mistakes were caught before release, including an accidental
Google subtask-create parent removal and lossy host argument parsing.

## Corrected failure paths

- Terminal raw-input lifetime, special keys, interrupts, settings handoff,
  button labels, disappeared controls, and original-interaction cleanup.
- Successful browser login minimizes its dedicated window where supported;
  the browser continues owning the authenticated session.
- Ordinary/terminal authentication share release gates. CLI caller checks,
  partial-session repair, cancellation before publication, panic-safe borrowed
  lease release, and concurrent lock creation preserve session isolation.
- OAuth grants bind provider authority/protocol/cloud, and public errors omit
  provider response bodies and descriptions.
- Complete bounded sources precede global mail/task sorting; provider-success
  failures preserve no-replay classification even when audit recording fails.
- Recipient reviews retain all addresses. Direct replies require the existing
  saved-draft review path to expose and bound provider-derived recipients.
- Calendar serialization preserves the reviewed instant, checks actual
  all-day boundaries, and rejects unresolved or ambiguous named-zone writes.
  Recurrence end dates and local expansion bounds are corrected.
- MIME flush ordering, charset decoding, attachment wrapping, Gmail body and
  label retrieval, and JMAP creation/submission/body contracts are corrected.
- Google task parent preservation, Todoist reminder-bound versions, TickTick
  cross-list listing, and post-write result classification are corrected.
- ICS staging retains original timezone/context; mixed MBOX parsing enforces
  remaining cumulative budgets before parsing more input.
- Host lifecycle checks require exact structured/scoped evidence and report
  potentially changed state after failed mutations. Printed commands preserve
  literal arguments.
- Public checker schema agreement, Windows output/download deadlines, and
  release archive path/type/duplicate/executable validation are corrected.
- Dormant messaging fixes cover rendered identity evidence, unknown counts,
  pagination, reaction ownership, and delegated edit responses. Gates remain
  closed; adapter corrections do not establish release evidence.

## Compatibility and recovery

OAuth grants from rc.5 and earlier require fresh explicit local authorization;
background refresh cannot upgrade their missing authority binding. Outlook
browser profiles are a separate session mechanism.

Reply and reply-all must first become saved drafts. Use `mail send-draft` on
accounts supporting exact-version draft submission; otherwise review and send
the draft in the provider UI. New-message and forward sends retain explicit
recipient inputs. See the [versioning exception](../adr/0020-public-and-local-versioning.md).

Mail/task projections require each account's complete result to fit 5,000
items and 2 MiB. Larger sources produce explicit per-account failures. Narrow
the query/status filter or use single-account reads. TickTick has its separate
documented provider bounds. Use UTC for an instant in a repeated named-zone
clock interval that an Outlook/Graph write cannot disambiguate.

ICS rescans may conservatively report a changed object/conflict because their
identity now includes the preserved source context. Text-only host inspection
cannot prove exact arguments and therefore cannot authorize automatic repair.

## Evidence limits

The integrated candidate passed `mise exec -- task verify`, including the
complete synthetic suite, race detector, static analysis, secret scan,
vulnerability/license checks, build, and release/workflow checks. The portable
PowerShell HTTP/message regressions also passed on macOS. Independent Codex
follow-up reviews found no remaining confirmed blocker after their reproduced
cancellation, recipient-review, and calendar-boundary findings were corrected.

The regression tests use synthetic accounts, messages, calendars, local
servers, DOM pages, PTYs, archives, and in-memory HTTP handlers. No real mail,
calendar, task, or messaging write was used for this audit. Provider contracts
were checked against primary documentation where relevant, including
[JMAP](https://www.rfc-editor.org/rfc/rfc8621.html),
[iCalendar](https://www.rfc-editor.org/rfc/rfc5545.html),
[Google Tasks move](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks/move),
and [delegated Teams edits](https://learn.microsoft.com/en-us/graph/api/chatmessage-update).

Passing this review does not prove the absence of other bugs or promote any
provider/platform row to live-observed. Windows installation, ACL, and native
shell runtime behavior require the Windows CI jobs; cross-compilation alone
is insufficient. Release artifacts are separately bound to the exact merged
commit, tag, workflow, checksum, and signature under [release engineering](../releasing.md).
