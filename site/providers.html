Providers

Supported services and how each one connects

Corresync doesn’t guess what an account supports from the provider’s name. It looks up public records without using credentials, and you choose the mail and calendar routes before signing in.

Check an address See the setup steps

Compatibility check

Check whether your address works

Type the email address you want to connect. Your browser sends only the domain (the part after the @) to our lookup service and keeps the rest.

Enter a complete email address, like you@example.com. Nothing is looked up until there’s a domain after the @.

Only the domain leaves your browser. The part before the @ stays on this page. It is not sent, stored, logged, or put in the address bar. The lookup service reads public DNS records, keeps nothing, and never starts a sign-in. To skip it, corr account discover you@example.com does the same lookup on your computer without credentials.

Apple iCloud

iCloud Mail and Calendar

corr setup recognises Apple’s documented address types, and custom iCloud domains whose service records are complete and verified. It suggests Apple’s published IMAP, SMTP, and CalDAV servers, and you review each identity and route before the account is added.

iC

Available now · guided preset

iCloud Mail + Calendar

Mail
IMAP reads and organization, with SMTP composition and sending
Calendar
CalDAV calendar discovery, reads, and reviewed writes
Sign-in
Apple app-specific password entered directly into the OS credential store

Corresync passes only a fixed service name and the handle you reviewed to the system prompt, and never reads the password. It shows when Mail and Calendar last signed in, separately, without reading any message or event content.

2F

Apple Account requirement

Two-factor authentication

Turn on two-factor authentication, then create an app-specific password on Apple’s account page. Guided setup opens that page only if you ask it to, after the account has been added locally.

Check Apple’s official iCloud Mail settings and app-specific password guide. This preset is tested against synthetic contracts and is live-unobserved until someone records an opt-in observation.

Google routes

Gmail, Google Calendar, and Google Tasks

Create a Desktop OAuth client in a Google Cloud project you control, then import its JSON during guided setup. Corresync’s own managed OAuth is not active; your client opens the normal Google sign-in in your browser. The route is tested against synthetic contracts and is live-unobserved.

Tasks
Date-only due dates, subtasks, ordering, source links, and polling for changes
Sign-in

OAuth sign-in happens in your normal browser. Gmail, Calendar, Meet, and Tasks use pinned Google API versions. Google Cloud setup, step by step.

Task routes

Task services

You choose the task route separately from mail and calendar. Sign-in, features, sync state, and reviewed writes are kept per account.

To

Available now · OAuth

Microsoft To Do

Task lists, create and update, complete and reopen, delete, recurrence, checklists, categories, and Graph delta sync with limits.

Uses a Microsoft Graph public client you are authorized to register and select.

Td

Available now · OAuth

Todoist

Projects, task writes and completion state, reminders, recurrence, subtasks, labels, assignment, exact date and time handling, and sync-token changes with limits.

Uses your public OAuth client with PKCE. Features that depend on your Todoist plan are shown as such.

Ti

Available now · OAuth

TickTick

Projects and Inbox, search, create, update, complete, delete, recurrence, checklists, labels, one assignee, ordering, and polling with limits.

Uses your confidential OAuth client. Its secret is kept in an approved credential store. Reopening tasks and replacing reminders are not claimed to work.

Open standards

JMAP, IMAP/SMTP, and CalDAV

Use the services your provider offers, in any combination. These routes require valid TLS. The credential comes from an OS keyring entry or from one approved credential helper, given by absolute path.

J

Mail

JMAP

Mail reads, drafts, sending where the server offers it, moves, state changes, and reviewed deletion, following RFC 8620.

If the account is read-only or the server lacks Submission, those actions are reported as unavailable.

IM

Mail

IMAP / SMTP

IMAP folders, reads, MIME, drafts, safe moves, and SMTP sending, with a Sent-mailbox result that can be checked.

Operations that need UIDPLUS or a Sent mailbox fail early instead of being emulated unsafely.

C

Calendar · Tasks

CalDAV

Separate VEVENT calendars and VTODO task lists, with size-limited reads, recurrence, sync tokens, and reviewed conditional WebDAV/iCalendar writes.

After sign-in, Corresync checks calendar scheduling and task support separately.

One account, two routes

Mail and calendar can use different protocols

You can pair IMAP/SMTP with CalDAV, or set up an account with only mail or only a calendar. The combined Google route uses your Desktop OAuth client. Each account has a stable internal ID, and its profiles, credentials, sync state, previews, and audit records are kept separate.

Limits

What Corresync does when a feature is missing

The features page lists what agents can do and how partial provider support is shown.

  • Provider limits are reported as capabilities or degradations in the result.
  • Automatic discovery never starts Google OAuth. It opens from a login command you run, or after you accept a sign-in request in your MCP client.
  • Graph authorization never starts from automatic discovery.
  • Meeting links are requested only from the calendar route you selected, and only when it reports support.
  • If the result of a write is unknown, you need to check it; it is never retried automatically.
