Google setup

Connect Google with your own OAuth client

Corresync’s own managed Google OAuth client is turned off, so you use a client from your own project. Create a Desktop OAuth client in a Google Cloud project you control. Corresync checks the downloaded file and stores its credential in your OS keyring. You sign in to Google in your normal browser.

Start the setupCompare providers
Your own OAuth client works now. Corresync’s managed OAuth is not active.

The adapters are tested against synthetic contracts and are live-unobserved. Your Google project’s audience, quota, and warnings, and your organization’s policy, still apply.

Steps

Set up a Google Cloud project

The pictures below are simplified sketches, not screenshots of a real account. Google sometimes renames menus, but the steps are the same.

01 · Project

Create or select a project you own

Open Google Cloud Console and use the project picker. Don’t reuse another application’s client or secrets.

02 · APIs

Enable only the APIs you need

Enable the Gmail API for mail, the Google Calendar API for Calendar and Meet event links, and the Google Tasks API only if you use Tasks.

03 · Audience

Choose the audience and scopes

Choose Internal only if the project belongs to one eligible Workspace organization; otherwise choose External. While the app is in Testing, add your account as a test user. Authorizations in Testing expire after seven days.

04 · Client

Create a Desktop app and download JSON

Under Clients, choose Desktop app, not Web application, service account, or API key. Download the JSON and keep it private.

Import the client

Import the JSON with guided setup

Run corr setup, select Google and the services you want, then choose “Import downloaded client JSON”. Check the client ID, loopback URI, scopes, and keyring handles it shows. Adding the account does not sign you in. 

$ corr setup
$ corr auth login --account personal
$ corr doctor --account personal

For scripts, use corr auth google-client import FILE --key HANDLE first. Don’t paste the credential into TOML, a shell argument, MCP, an issue, or a support request. Corresync does not delete the downloaded file for you.

Verification and limits

Google verification and its limits

Google currently says verification is not required for personal use with fewer than 100 users or for qualifying internal use. Unverified-app warnings, user caps, restricted-scope policy, organization controls, and Google’s current terms still apply. Check Google’s official rules before moving from Testing to production.

  • In Testing, only listed test users can sign in, and authorizations expire after seven days.
  • A Workspace administrator can block or require review of the exact client ID and scopes.
  • Don’t use service accounts, domain-wide delegation, or weaker controls to get around this.
  • An agent cannot start Google sign-in by itself. It can ask, your MCP client asks you, and the sign-in opens only if you accept, and only for an account you already signed in to once from the terminal.
