Features

What Corresync does and where it stops

The CLI, your scripts, and MCP agents all use the same code, so everything below works the same way from each of them. What an account can do depends on its provider route (check yours first). If something is missing, Corresync says so instead of hiding it or faking it.

Mail and calendar

Mail and calendars across accounts

Reads can cover every account you connect, and each result shows its account, provider, and time zone. Each write targets exactly one account, and important changes are previewed first.

Mail

Lists and searches never include bodies or attachments. You read a body or an attachment with a separate, size-limited request.

  • Search one account or all of them; if some fail, the result says which
  • List folders and messages; read a body or one attachment on request
  • Save drafts that can never send themselves
  • Send, reply, reply-all, and forward, as text or HTML, with size-limited attachments
  • Move messages, set read state, and permanently delete where the provider supports it, each with a review

Every write is attempted once. If the result is unknown, Corresync tells you to check it and does not retry automatically.

Calendar and agenda

One agenda for all accounts. Each event shows its original calendar, time zone, and provider.

  • Discover selectable calendars per account
  • List a time range, or one agenda across accounts
  • Create, update, and cancel events, with a preview before each change
  • Create, replace, and remove recurrence where supported
  • Required and optional attendees; the review says whether the route notifies them
  • Meeting links only where the provider offers them: Teams on Microsoft routes, Google Meet when the calendar advertises it

Agents and scripts

AI agents and scripts

MCP tools and --json output run the same code and the same checks as the interactive CLI.

AI agents (local stdio)

Corresync provides 72 tools and two read-only monitor resources. There is no HTTP, SSE, remote endpoint, or hosted relay.

  • Tools return metadata before content, and every result names its account
  • Every important write has separate preview and commit tools
  • Adding or removing accounts and changing settings also use a preview and a commit
  • Agents can add, rename, and remove accounts through those tools
  • Signing in, turning on monitoring, approving a runner or remote egress, purging queues, imports, and binary updates can only be done by a person in the CLI
  • Tool annotations help the client’s interface but never replace Corresync’s own checks

Connect your client: Codex, Claude Code, GitHub Copilot CLI, Gemini CLI, Qwen Code, Qoder, Kimi Code CLI, or any stdio MCP client.

Scripts (stable JSON)

Add --json to a command and it prints exactly one plain JSON value on stdout. 

corr mail search --all-accounts \
    --query 'subject:"quarterly plan"' --json

JSON output follows the same account separation, size limits, and preview rules as the rest of the CLI.

Local features

Features that are off until you turn them on

Read-only import staging

Scan one local source you approved (a recognized archive or export, a Maildir tree, or a Thunderbird profile) into a size-limited staging area for one account.

  • Nothing is scanned until you run the command again with read approval
  • It never signs in, uploads, sends, or changes the source
  • Purge removes only Corresync’s staging data, never your files

Opt-in monitoring

Monitoring is off for every account. You turn it on one step at a time: off → local notification → durable queue → one approved runner.

  • Quiet hours, debounce, hourly limits, deduplication, and a circuit breaker
  • Desktop notifications use local tools on Linux and macOS. They don’t work on Windows (no registered AppUserModelID), but queue and runner modes do
  • The runner is one program, given by absolute path, started without a shell and given size-limited JSON. Sending data off the machine needs its own approval

Feedback reports

corr feedback builds a report on your computer that contains only allowlisted fields: build, platform, install method, whether the config is valid, summary capabilities, and optionally a sanitized error class.

  • Addresses, credentials, content, queries, and private paths can’t be included
  • Building the report makes no network request
  • Copying, saving, or opening a prefilled GitHub page each needs its own flag, and none of them submits anything
  • A separate option, off by default, can submit a smaller public issue with only allowlisted fields through your signed-in GitHub CLI after an interactive failure

FAQ

Common questions

Will it work with my accounts?

Outlook Web, Microsoft Graph, Todoist, TickTick, JMAP, IMAP/SMTP, and CalDAV routes are available now; Gmail, Google Calendar, and Google Tasks use a Desktop OAuth client in a Google Cloud project you control. You pick mail and calendar routes separately for each account, and anything that doesn’t work is reported. The optional compatibility checker sends only the domain after the @, or you can skip it and run the lookup locally after installing.

Does it cost anything?

No. Corresync is open source under the Apache-2.0 license. You bring the accounts you already have. Microsoft Graph needs a public OAuth client you are authorized to use; Google needs your own Desktop OAuth client. Corresync’s own managed Google OAuth is not active.

Where does my mail live?

With your provider, as before. Corresync runs entirely on your computer. There is no hosted relay and no cloud copy. Local state such as sync cursors, staging, queues, and pending previews is stored locally, separately for each account.

Can an AI agent send something without me?

An important write first returns a review of exactly what will happen. It only goes ahead with that exact reviewed content. The approval is short-lived, works once, and only for that caller, account, target, and content. Read the safety model.

Does Corresync phone home?

There is no telemetry pipeline or raw crash upload. The interactive CLI may check for a newer public release. That check sends only the Corresync version string, is cached for 24 hours, does not run for MCP, pipes, or JSON output, and can be turned off in the configuration. A separate feedback option, off by default, can use your signed-in GitHub CLI to post a small public issue with only allowlisted fields after an interactive failure. Since 0.9.2, new standalone configurations turn on verified automatic updates; existing settings are not changed and installation can be turned off. Signed preview releases are opt-in. Package managers get stable releases only, and Corresync does not update an install that a package manager owns.

What if a send fails halfway?

Every write is attempted once. If the provider may have made the change but did not confirm it, Corresync stops and asks you to check, rather than retrying and risking a duplicate.

Limits

What Corresync does not do

Differences between accounts, such as a JMAP server without submission or an IMAP server without UIDPLUS, are reported as capabilities and degradations. Corresync does not quietly switch to another route.

  • Google connections require your own OAuth client. Guided setup checks a downloaded Desktop client and stores its credential and each account grant in the OS keyring. Setup guide.
  • No token relay. Microsoft Graph uses a public client you register and are authorized to use.
  • Teams chat and channels are a preview. You can select them in setup, but they lack complete live compatibility evidence. Calls, recordings, presence, and meeting lifecycle management are out of scope.
  • No mailbox-rule or delegate-permission management, generic provider property access, or arbitrary provider actions.
  • No unattended login, tenant-wide access, or TLS interception. Sign-in is visible and handled by the provider.
  • No Windows desktop notifications yet. Queue and approved runner modes work.

Evidence

How compatibility is tested

Every v0.9 provider route is tested against deterministic synthetic provider contracts and at the application level. That tells you the code does what the contract says. It does not tell you a real provider behaves the same way. Every route is live-unobserved until a separately authorized, content-free observation is recorded for the exact Corresync commit, provider route, and platform. An older Google observation covered only the retired Gmail IMAP/SMTP transport.

A missing observation is never counted as a pass, and the default tests and CI never touch a real mailbox or calendar. Check the current evidence before connecting an account you consider sensitive.
