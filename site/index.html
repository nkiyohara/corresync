Every inbox and calendar. One guarded core.

Corresync is a multi-account mail and calendar bridge: a short corr CLI for you and your scripts, plus a local MCP server for agents. Accounts stay isolated, providers stay explicit, and every consequential write is reviewed before commit.

Bring the route you actually use

Web session, provider API, or open standard.

One account can use different mail and calendar routes. Corresync makes that choice visible instead of guessing from an address or silently falling back.

Provider-native

Outlook Web, Google API, Microsoft Graph

Use an interactive Outlook Web session, or explicitly configure a public OAuth client with PKCE for Google or Graph. Grants stay in the operating-system keyring; no shared client secret or hosted token relay exists.

Standards-first

JMAP, IMAP/SMTP, and CalDAV

Combine the standards your provider exposes—for example IMAP/SMTP mail with a CalDAV calendar. Configuration stores only typed endpoints and an approved keyring/helper reference, never a password.

Credential-free discovery ranks evidence but never authenticates or adds an account. You select each route explicitly. See the provider and degradation matrix.

Short command, explicit setup

Install. Choose. Connect.

One local package, one account decision, then ordinary flags or ordinary language.

  1. 01

    Install and verify

    # macOS or Linux
brew install nkiyohara/corresync/corresync

# Windows
winget install --id nkiyohara.Corresync --exact

corr --version
corr config init
corr completion install

    Scoop, direct downloads, checksums, Sigstore provenance, and native Linux packages are in the install guide. Completion detects Bash, Zsh, or Fish and is idempotent.

  2. 02

    Add and authenticate an account

    corr account discover reader@example.invalid
corr account add reader@example.invalid --help
corr account list
corr auth login --account work
corr doctor --online --account work

    Discovery uses no credentials. Account creation shows the route, authentication type, capabilities, and degradation boundary before saving. Monitoring remains off.

  3. 03

    Connect an agent—or use the CLI

    corr mcp setup codex
# or: claude-code, github-copilot,
#     gemini-cli, qwen-code, qoder

$ corr agenda list --all-accounts \
    --start 2026-07-28T00:00:00Z \
    --end 2026-07-29T00:00:00Z

    Agents, scripts, and humans reach the same typed use cases, policy checks, and stable JSON shapes.

Safety is the architecture

Agents get typed tools. Never your credentials.

CLI and MCP enter the same application core. A config-scoped local owner holds provider clients; endpoint authentication completes before its rotating bearer is transmitted.

AI agentsMCP · stdio

You & scriptsCLI

typed core · policyauthenticated IPCsession owneraccount-isolated clientsTLSexplicit providers

  • Metadata first. Lists omit bodies and bytes; sensitive reads stay separate.
  • Preview binds commit. Caller, account, provider, target, payload, expiry, and one use.
  • Fail closed. An ambiguous write is never retried automatically.
  • Untrusted by default. Mail, events, imports, and queue values are data—not instructions.
  • No ambient listener. MCP is stdio; daemon IPC is a Unix socket or Windows named pipe.
  • Private support. corr feedback is allowlisted, local, visible before action, and never auto-submits.

Local-first workflows

Beyond one inbox

  • Multi-account projections. Search mail and list an agenda across isolated accounts with provenance and partial failures.
  • Read-only import staging. Inspect recognized exports, archives, Maildir, and Thunderbird profiles without uploading or changing the source.
  • Opt-in monitoring. Move deliberately from off to supported local notification, durable queue, and finally an approved runner.
  • Separate egress consent. Remote runner disclosure is never implied by collection or local execution.
  • Privacy-preserving feedback. Generate a redacted report locally, inspect it, then explicitly copy, save, or open GitHub.

Automatic agents are read-only by default. Every external write still goes through the same preview/commit boundary. Explore the CLI →

Command transition

Corresync is the product. corr is the command.

Existing 0.7 scripts receive a finite compatibility window, while new setup converges on the short command. Product-scoped package, repository, config/state, plugin, and MCP names remain corresync.

  • 0.8 and 0.9 archives/packages carry identical corr and compatibility executables.
  • Completions, manuals, help, MCP registrations, and new examples use corr.
  • Schema v3 preserves account IDs while introducing explicit mail/calendar routes.
  • Former project names are accepted only by the finite v0.6 migration path.
  • Pages intentionally has no legacy redirect.
