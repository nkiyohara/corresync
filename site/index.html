Bring the route you already use

Provider-native when useful. Standards-first when available.

Mail and calendar routes are selected independently, so one account can pair IMAP/SMTP mail with a CalDAV calendar—or use one native route for both.

Browser-owned

Outlook Web and Google Web

Keep interactive sign-in in a dedicated visible browser. Google Web is a bounded read-only option; Outlook Web supports typed mail and calendar operations.

Explicit OAuth

Google API and Microsoft Graph

Bring a public-client registration you are authorized to use. Corresync shows service-minimal scopes and keeps grants in the OS keyring—never in configuration.

Open standards

JMAP, IMAP/SMTP, and CalDAV

Use encrypted standards endpoints with an OS-keyring entry or one explicitly approved credential helper reference.

Evidence, stated plainly. Every v0.8 route is covered by synthetic provider contracts. The v0.8 provider and platform implementations remain live-unobserved until an authorized, commit-bound record exists.

Five minutes to a first read

Install. Sign in. Ask.

Start with Outlook Web using the default configuration, or discover another route without sending credentials.

  1. 01

    Install and verify

    # macOS or Linux
brew install nkiyohara/corresync/corresync

# Windows
scoop bucket add corresync \
  https://github.com/nkiyohara/scoop-corresync
scoop install corresync/corresync

corr --version

    Direct archives, Linux packages, checksums, Sigstore provenance, and current WinGet status are in the install guide.

  2. 02

    Initialize and sign in

    corr config init
corr config validate
corr auth login
corr mail folders
corr calendar folders

    The default route opens Outlook Web in a dedicated browser profile. SSO, MFA, Conditional Access, and organization notices stay in the provider-owned flow.

  3. 03

    Connect an agent—or keep using the CLI

    # choose the client you use
corr mcp setup codex
corr mcp setup claude-code
corr mcp setup github-copilot
corr mcp setup gemini-cli
corr mcp setup qwen-code
corr mcp setup qoder

corr agenda list --all-accounts \
  --start 2026-07-29T00:00:00Z \
  --end 2026-07-30T00:00:00Z

    Generic MCP clients use corr mcp serve. Every client reaches the same 40 narrow tools and two read-only monitor resources.

Safety you can see

Nothing sends on the first attempt.

A consequential command first returns a review. Approval stays bound to that caller, account, provider, target, payload, expiry, and one use.

  • Credentials stay out of config. Passwords, cookies, and OAuth grants have no TOML field.
  • Unknown means stop. An ambiguous remote write is never retried automatically.
  • Monitoring starts off. Collection, runner use, and remote egress are separate choices.
  • Mailbox content is untrusted data. It is never authority to run a command or start an agent.

Honest edges

Clear limits are part of the product.

  • Google Web is read-only. Use Google API explicitly for supported writes.
  • OAuth routes are bring-your-own public clients. Corresync does not ship a shared client or relay.
  • Windows desktop notifications are unavailable. Queue and approved runner modes remain available.
  • Provider support is evidence-scoped. Synthetic contracts do not become live compatibility claims.
  • No Teams chat or meeting lifecycle management. Only provider-native join links on one calendar event are in scope.
