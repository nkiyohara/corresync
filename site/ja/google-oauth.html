Google OAuthの設定

自分のOAuthクライアントでGoogleに接続する

Corresync側のOAuth審査を待たずに使えるよう、自分で管理するGoogle Cloudプロジェクトに「デスクトップアプリ」のOAuthクライアントを作ります。Corresyncはダウンロードしたファイルを検証し、その認証情報をOSのキーチェーンに保存します。ログイン、MFA、同意の操作は、普段のブラウザに表示されるGoogleの画面で行います。

設定手順対応状況
自分で用意するOAuthクライアントは利用できます。Corresyncが管理するOAuthは無効のままです。

アダプターは合成データでの契約テストのみで、現在のバージョンでの実環境の確認は記録されていません。Google側のAudience、割り当て、警告、組織のポリシーは通常どおり適用されます。

ブラウザでの4つの手順

必要最小限のGoogleプロジェクトを作る

下の図は実際のアカウント画面ではなく、迷いやすい箇所を示した説明図です。Googleがメニュー名を変えても、選ぶものとセキュリティ上の注意点は変わりません。

01 · プロジェクト

自分が所有するプロジェクトを選ぶ

Google Cloud Console上部のプロジェクト選択から、プロジェクトを作成または選択します。ほかのアプリのクライアントや認証情報は使い回さないでください。

02 · API

使うサービスのAPIだけを有効にする

メールにはGmail API、カレンダーとMeetリンクにはGoogle Calendar APIを有効にします。Google Tasks APIはタスクを使う場合だけ有効にします。

03 · Audience

対象ユーザーとスコープを実態に合わせて選ぶ

1つのWorkspace組織の中だけで使う条件を満たす場合はInternal、それ以外はExternalを選びます。Testingの間は、接続するアカウントをテストユーザーに追加してください。Testingでの認可は7日で失効します。

04 · クライアント

デスクトップアプリを作り、JSONをダウンロードする

Clientsで「デスクトップアプリ」を選びます。ウェブアプリケーション、サービスアカウント、APIキーは選ばないでください。ダウンロードしたJSONは他人に見せないように保管します。

Corresyncへの取り込み

ガイド付き設定でJSONを取り込む

corr setupを実行し、Googleと使いたいサービスを選んでから、「ダウンロードしたクライアントJSONを取り込む」を選びます。クライアントID、ループバックURI、スコープ、キーチェーンの個別のハンドルを確認します。この時点ではまだログインしません。 

$ corr setup
$ corr auth login --account personal
$ corr doctor --account personal

スクリプトから設定する場合は、最初にcorr auth google-client import FILE --key HANDLEを実行します。生成された認証情報を、TOML、コマンドの引数、MCP、Issue、サポート用の出力に貼り付けないでください。ダウンロードしたファイルは、Corresyncが削除することはありません。

公開ステータスを変える前に

審査と利用上の制限

Googleは現在、ユーザーが100人未満の個人利用や、条件を満たすInternalでの利用を、審査が必須ではない例として挙げています。ただし、未確認アプリの警告、ユーザー数の上限、制限付きスコープの方針、組織の管理設定、Googleの最新の規約は別に適用されます。

  • Testingでは登録したテストユーザーしか使えず、認可は7日で失効します。
  • Workspaceの管理者は、特定のクライアントIDとスコープをブロックしたり、審査の対象にしたりできます。
  • これらの制限を避けるために、サービスアカウントやドメイン全体の委任を使わないでください。
  • MCPは認証済みのセッションを使えますが、Google OAuthを開始することはできません。
