スタートガイド

インストールから最初の質問まで4つの手順

corrをインストールし、仕事用や個人用のアカウントを追加して、ローカルのMCPサーバーをエージェントに登録します。複数のアカウントをまとめて検索しても、サインインと権限はアカウントごとに別です。Outlook Webのサインインはブラウザが、APIやオープン標準で使う認可情報はOSキーチェーンが管理します。MCPはこのコンピューター上のstdioだけで動きます。

手順1から始める先に対応状況を確認
  1. 1

    corrをインストール

    この手順ではcorrコマンドを入れるだけです。アカウントの追加やサインインはまだ行いません。

    macOS · Linux

    curl -LsSf https://corresync.org/install.sh | sh

    検証済みの安定版を現在のユーザー向けにインストールします。実行前にスクリプトの中身を確認できます。

    Windows · PowerShell

    powershell -NoProfile -Command "irm https://corresync.org/install.ps1 | iex"

    管理者権限は使わず、ユーザーのPATHだけを更新します。実行前にスクリプトの中身を確認できます。

    パッケージマネージャーでインストール

    この場合、更新と削除もパッケージマネージャーで行います。

    Windows · WinGet

    winget install --id nkiyohara.Corresync --exact

    Microsoftの審査を通ったmanifestを使います。

    macOS · Linux · Homebrew

    brew install nkiyohara/corresync/corresync

    Homebrewが最新の安定版タグのソースからビルドします。

    Windows · Scoop

    scoop bucket add corresync https://github.com/nkiyohara/scoop-corresync
scoop install corresync/corresync

    チェックサムを固定したCorresync用のbucketを使います。

    Linux向け.deb、.rpm、.apkパッケージ、アーカイブ、チェックサム、Sigstoreの来歴情報、Claude Desktop用の.mcpbは最新リリースにあります。

    動作確認

    corr --version

    自動更新 · 既存の設定で有効にする場合 

    corr config set updates.auto_install true

    0.9.2以降、新しく作った設定では、署名を検証した自動更新が有効になります。既存の設定は変わらないので、有効にする場合はこのコマンドを実行してください。MCPや機械可読出力から更新が始まることはありません。無効にするにはcorr config set updates.auto_install falseを実行します。

    任意 · 署名済みのプレビュー版を使う場合 

    corr config set updates.channel preview
corr update

    既定は安定版です。安定版に戻すにはcorr config set updates.channel stableを実行します。自動でダウングレードすることはありません。

    macOS版はDeveloper IDで署名し、Appleの公証（notarization）を受けています。Windows版はまだAuthenticodeで署名していません。警告を無視して実行せず、チェックサムと署名付きの来歴情報を確認してください。

  2. 2

    メールとカレンダーのアカウントを設定

    実行するコマンドは1つです。メールアドレスを入力すると、認証情報を使わずにメールとカレンダーのサービスを調べ、最後に確認画面を出してからアカウントを追加します。

    サインインや外部の認証情報へのアクセスは、追加した後に別の操作として選びます。続けて接続の確認や2つ目のアカウントの追加もできます。corr settingsでも同じ画面を開けます。スクリーンリーダーを使う場合はCORRESYNC_ACCESSIBLE=trueを設定すると、1行ずつの対話形式になります。入力の途中でやめるには:cancelと入力してください。

    Outlook Webは、プロバイダーのサインイン画面をブラウザで開いてサインインします。Microsoft Graph、JMAP、IMAP/SMTP、CalDAVは、プロバイダーが対応していて、必要な接続方法や認証情報の保存先を自分で選んだ場合に使えます。サービスを調べる段階で、ブラウザを開いたり、キーチェーンを読んだり、管理者の同意を求めたりすることはありません。

    iCloudの場合：corr setupは、@icloud.com、@me.com、@mac.comのアドレスと、必要なサービスレコードがすべて確認できたカスタムiCloudドメインについて、iCloudのメールとカレンダーをまとめて提案します。アカウントを追加した後、Appleの2ファクタ認証とアプリ用パスワードについて説明します。パスワードはOSの入力画面に直接入力するので、Corresyncには渡りません。

    Googleの場合：自分で管理するGoogle CloudプロジェクトでデスクトップOAuthクライアントを作ります。ガイド付き設定が、ダウンロードしたJSONを検証してから、その認証情報をOSキーチェーンに保存します。

    アドレスを送信せずに対応状況を確認 · サインインの仕組み

    ガイド付き設定 · おすすめ

    corr setup

    ローカルの設定状況を確認し、必要ならシェル補完を追加して、終わっていない手順から再開します。アカウントの接続方法は保存前に確認でき、認証は別の操作です。見つかったエージェントの中から複数を選ぶと、ローカル設定の変更内容をまとめて確認した後、エージェントごとに適用して動作を確認します。

    スクリプトで設定する場合

    corr setup you@example.com --alias personal
corr auth login --account personal
corr doctor --account personal

    これらのコマンドは対話なしで動くので、スクリプトから使えます。

    iCloudメール＋カレンダー · 利用可能

    ガイド付きのプリセットで両方のサービスを追加し、確認済みの認証情報ハンドルを1つ共有できます。最後に認証できた状態は、メールの内容を読まずに確認できます。接続する前にAppleのアプリ用パスワードの説明を読んでください。

    Gmail · Googleカレンダー · Google Tasks

    Google OAuthの設定ガイド（画面付き）に沿って、デスクトップクライアントを作り、必要なサービスだけを選びます。クライアントの認証情報とアカウントの認可はOSキーチェーンに保存されます。

  3. 3

    エージェントに接続

    クライアントの設定ファイルに、ローカルのstdio MCPサーバーを絶対パスで登録します。リモートのエンドポイントは作りません。登録したらクライアントを再起動してください。

    Codex

    corr mcp setup codex

    codex mcp get corresyncで確認できます。

    Claude Code

    corr mcp setup claude-code

    ユーザー単位かプロジェクト単位で登録できます。

    GitHub Copilot CLI

    corr mcp setup github-copilot

    copilot mcp get corresyncで確認できます。

    Gemini CLI

    corr mcp setup gemini-cli

    gemini mcp listで確認できます。

    Qwen Code

    corr mcp setup qwen-code

    qwen mcp listで確認できます。

    Qoder

    corr mcp setup qoder

    qodercli mcp listで確認できます。

    Kimi Code CLI

    corr mcp config kimi-code

    KimiのMCP設定に追加する内容を表示します。

    その他のMCPクライアント

    corr mcp serve

    stdioで通信するコマンドとして、任意のクライアントに登録できます。

    どのクライアントからも同じツールを使い、同じポリシーチェックがかかります。CodexとClaude Code向けにはPluginとAgent Skillも同梱しています。

  4. 4

    複数アカウントにまたがる質問

    読み取りは複数のアカウントにまたがって実行でき、結果はアカウントごとに区別されます。書き込みには必ず確認の手順が入ります。

    • 「Anaから来た四半期計画のメールを、全アカウントから探して」
    • 「明日の午前中の予定を、すべてのカレンダーから教えて」
    • 「Anaへの返信を下書きして。送る前に自分で確認する」

    結果にはアカウントとプロバイダーが表示されます。一部のアカウントで失敗した場合は、成功した分の結果と合わせて、失敗したことを示します。

    送信を頼むと、まず送信する内容そのものを示す確認画面が返ります。アカウント、宛先、本文のバイト列が一致する場合だけ、CLIの--approveかMCPの確定用ツールで送信できます。承認の有効期限は短く、1回しか使えません。
