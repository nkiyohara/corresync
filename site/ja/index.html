メール・予定・タスクのためのローカルMCPサーバーとCLI

仕事用と個人用のメール、予定、タスクを、Codex、Claude Code、その他のMCP対応エージェント、ターミナルから扱えます。検索、整理、返信、送信などは共通のツールで行い、サインインと権限はアカウントごとに分けて管理します。

対応サービス：Outlook · Gmail · Googleカレンダー · Microsoft To Do · Todoist · TickTick · オープン標準。使える接続方法と機能はアカウントごとに表示します。サービス別の詳細

AI エージェントでセットアップ メールアドレスで対応状況を確認

サインインはブラウザまたはOSキーチェーンの中で行われ、Corresyncが扱う認証情報をエージェントが持つことはありません。Corresyncの中継サーバーもありません。送信などの操作は、プレビューを確認して承認するまで実行されません。

セットアップ

手元のAIエージェントに、Corresyncのインストール・更新と同梱のAgent Skillの導入を任せられます。変更は自分で確認して承認します。

おすすめはスタンドアロン版のCLIです。新しくセットアップすると、検証済みの自動更新が有効になります。すでにインストールしている場合は、パッケージマネージャーでの管理、既存の設定、自動更新の設定をそのまま引き継ぎます。変更するかどうかは自分で選べます。

Codex で設定 Claude Code で設定

使っているデスクトップアプリのボタンを押すと、セットアップ依頼が入力された状態でアプリが開きます。内容を確認してから自分で送信してください。

このコンピューターを操作できるChatGPT CodexまたはClaude Codeのデスクトップアプリが必要です。権限の確認が表示されたら承認してください。管理者権限は不要です。アカウントへのサインインと多要素認証は自分で行い、パスワードや確認コードはチャットに貼り付けないでください。

スマートフォンで見ている場合は、セットアップするコンピューターでこのページを開くか、手順をコピーしてそのコンピューターに送ってください。

corr setup

corr setupは、途中まで済んだ設定があればそこから続けます。アカウントの接続方法は認証情報を使わずに調べます。アカウントとエージェントの設定変更は適用前に内容を確認でき、サインインはその後に別の操作で行います。ほかのインストール方法やMCPクライアントごとの設定はスタートガイドにあります。

インストール後の手順

アカウント追加から質問まで

プロバイダーは自動では選ばれません。まず認証なしでアドレスの接続方法を調べ、使う方法を決めてアカウントを追加します。サインインはその後です。

1 · アカウントを追加してサインイン 

corr setup you@example.com --alias personal
corr auth login --account personal

接続方法を調べるだけでは何も開きません。サインインは次のログインコマンドで、選んだ接続方法を使って行います。

2 · エージェントにつなぐ

corr integrations setup codex

エージェントにローカルのstdioサーバーを登録します。登録後にクライアントを再起動してください。

3 · エージェントに頼む

› 今日の正午までに対応が必要なことを、
  全アカウントから教えて

エージェントはCorresyncのツールを呼び出します。回答にはどのアカウントの情報かが表示されます。

使用例

複数アカウントのメールと予定をまとめて調べる

CLIとMCPは同じ処理を呼び出し、アカウントの分離やポリシーのチェックも共通です。以下の例はどちらからでも使えます。

全アカウントのメール検索

「四半期計画のスレッドを探して。仕事用か個人用かは覚えていない」 

$ corr mail search --all-accounts \
    --query 'subject:"quarterly plan"'
● work · microsoft-owa  Ana Ruiz  Plan review
· personal · jmap   Finance      Plan receipt

失敗したアカウントがあれば、部分的な結果であることを示します。

今日の予定の一覧

「仕事と個人、両方のカレンダーから今日の予定を教えて」 

$ corr agenda list --all-accounts \
    --start 2026-07-29T00:00:00Z \
    --end 2026-07-30T00:00:00Z
09:30 work      Design review · Teams
12:30 personal  Dentist

各予定にはタイムゾーン、カレンダー、プロバイダーの情報が付きます。

送信前の内容確認

「Anaへの返信を下書きして。送信は自分で承認する」 

› Anaへの返信を下書きして
  mail_send
REVIEW · send new message
  to    ana@example.invalid
  body  text/plain · 412 B
この内容を承認するまで送信されません。

確認したときとアカウント、宛先、本文が完全に一致する場合だけ送信できます。

安全性

送信は確認してから

送信のように結果が残る操作は、最初の呼び出しでは実行されず、確認用のプレビューを返します。承認は、そのときの呼び出し元、アカウント、プロバイダー、対象、内容にだけ有効で、期限があり、1回しか使えません。

  • エージェントが使えるのはツールだけです。パスワード、Cookie、OAuthの認可情報は、MCPのツールにも設定ファイルにも出てきません。
  • ローカルで動きます。MCPサーバーはこのコンピューター上でstdioを使って動き、外部の中継やリモートのエンドポイントはありません。
  • 結果がわからない書き込みは再試行しません。成功したかどうか判断できない書き込みは、自動で再試行せずに止まります。
  • メールの内容は信頼しないデータとして扱います。メールに何が書かれていても、それを根拠にコマンドの実行やエージェントの起動が許可されることはありません。

接続方法

各サービスのAPIとオープン標準

メールとカレンダーの接続方法は別々に選べます。たとえばメールはIMAP/SMTP、カレンダーはCalDAVという組み合わせもできます。

ブラウザでサインイン

Outlook Web

Outlookへのサインインは、専用に開く画面付きのブラウザで自分で行います。その後、メールと予定を操作できます。

OAuth

Microsoft Graph · Googleは自分のクライアントで

Microsoft Graphは、利用を許可されている公開クライアントを指定して使います。Gmail、Googleカレンダー、Google Tasksは、自分のGoogle Cloudプロジェクトで作ったデスクトップOAuthクライアントを使います。

オープン標準

JMAP、IMAP/SMTP、CalDAV

暗号化された接続を使います。認証情報はOSキーチェーンか、自分で許可した認証ヘルパーから読み込みます。

追加する前に条件を確認できます。 サービス一覧に、サインイン方法、設定に必要なもの、アカウントによって変わる機能をまとめています。

制限事項

現在の制限

対応範囲とその根拠はできることのページにまとめています。

  • Gmail、Googleカレンダー、Google Tasksには自分のOAuthクライアントが必要です。ガイド付き設定で、クライアントの秘密値をOSキーチェーンに保存します。
  • Microsoft GraphのOAuthクライアントは自分で用意します。Corresyncはトークンの中継サーバーを運営していません。
  • Windowsのデスクトップ通知には対応していません。キューと承認済みランナーは使えます。
  • 機能はアカウントごとに確認します。 メールアドレスのドメインから推測せず、設定時にそのアカウントで使える接続方法とサービスを表示します。
