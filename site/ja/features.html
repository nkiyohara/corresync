できること

機能と制限

複数のアカウントのメールや予定をまとめて検索しても、アカウントの情報は混ざりません。CLIとMCPは同じ処理を呼び出し、権限の確認と「プレビュー→実行」の流れも共通です。このページでは、できることと一緒に制限も説明します。

スタートガイド対応サービスを確認

メールと予定

複数アカウントのメールと予定

読み取った結果には、どのアカウント、どのプロバイダーのものかが表示されます。書き込みは、対象のアカウントを1つに決めてから行います。

01

メール

  • フォルダーとラベルの一覧、使える機能の確認
  • 件数に上限のある一覧表示、検索、スレッド検索
  • 指定したメッセージのヘッダー、本文、添付ファイル（サイズ上限あり）の読み取り
  • 下書きの作成・更新、返信、転送、送信
  • 既読・未読、アーカイブ、移動、ゴミ箱への移動
  • 複数アカウントの検索（失敗したアカウントがあれば結果に表示）

送信、移動、削除などは、まず確認用のプレビューを返します。確認した内容のまま、1回だけ実行できます。

02

カレンダーと予定

  • 使えるカレンダーの中から選択
  • 期間を区切った予定一覧と、複数アカウントの予定一覧
  • タイムゾーンと繰り返し予定の情報を保持
  • 予定の作成・更新・キャンセル
  • 接続方法が対応している場合だけ、TeamsまたはGoogle Meetのリンクの作成を依頼
  • 会議リンクは1つの予定の属性として保存

Teamsのチャットとチャネルはプレビューとして選択できますが、実環境での確認はまだそろっていません。通話、録画、プレゼンス、会議のライフサイクル管理は対象外です。

エージェントとスクリプト

AIエージェントとスクリプトからの利用

MCPだけに許された特別な操作はありません。CLIとMCPは同じアプリケーションの処理を呼び出します。

03

AIエージェント（ローカルのstdio経由）

  • 用途を絞ったメール・カレンダー用のツール
  • 認証情報、Cookie、任意の操作、汎用のプロパティAPIはツールとして提供しない
  • 読み取りのツールと、書き込みのプレビュー用・実行用のツールは別
  • 結果にはアカウントとプロバイダーを表示
  • リモートのMCPエンドポイントは作らない
corr mcp setup codex

04

スクリプト（JSON出力）

  • 人が読む表示と、機械可読のJSON出力は別
  • アカウントの選び方とポリシーのチェックはCLIと同じ
  • 一部の失敗、機能の制限、結果不明もそのまま出力
  • stdoutにデータ、stderrに診断情報を出力
  • スキーマはバージョンポリシーに沿って変更
corr agenda list --all-accounts --format json

自分で有効にするローカル機能

オプトインの機能

読み取り専用のインポート（一時領域）

ほかのアプリの設定を読み取って候補を表示します。そのアプリの秘密情報は使わず、アカウントの追加や認証も行いません。

モニタリング

初期状態では無効です。アカウント、検索条件、間隔、通知先を指定したときだけ、このコンピューター上で動きます。MCPから有効にすることはできません。

フィードバック

自動では送信されません。共有する前に内容を確認でき、メール本文、宛先、トークン、認証情報は含まれません。

更新の検証

更新時には、署名付きのチェックサムと来歴情報を確認します。パッケージマネージャーでインストールした場合は、そのパッケージマネージャーで更新します。

よくある質問

インストール前によくある質問

自分のアカウントで使えますか？

Outlook Web、自分で設定したMicrosoft Graph、Todoist、TickTick、JMAP、IMAP/SMTP、CalDAVが使えます。Gmail、Googleカレンダー、Google Tasksは、自分で管理するGoogle CloudプロジェクトのデスクトップOAuthクライアントを使って接続します。対応状況はドメインだけを送る確認ページで調べられます。

料金はかかりますか？

CorresyncはApache-2.0ライセンスのオープンソースソフトウェアです。プロバイダー、クラウド、エージェント、通信の料金は、それぞれのサービスの条件によります。

メールはどこに保存されますか？

メールはプロバイダーとこのコンピューターの間で直接やり取りされます。Corresyncが運営するメールボックスやトークンの中継サーバーはありません。ローカルのキャッシュやカーソルはアカウントごとに分かれています。

AIが勝手に送信することはできますか？

できません。最初の呼び出しでは確認用のプレビューが返るだけです。送信するには、その内容に対する承認が必要で、承認は有効期限が短く、1回しか使えません。

勝手に外部と通信しませんか？

アクセス解析やテレメトリーはありません。通信するのは、Webサイトの任意の対応状況チェック、明示的に実行する更新確認、選んだプロバイダーへの操作、オプトインのフィードバックなど、目的がはっきりしたものだけです。

送信の途中で結果がわからなくなったら？

自動では再試行しません。二重送信を防ぐために「結果不明」として止まり、状態の照合を求めます。

対応しないこと

意図して対応していない機能

製品の対象範囲に入っていることと、今の接続方法で使えることは別です。

  • ホスト型のリレー、マルチユーザーのサーバー、リモートのMCP接続
  • 無人での認証情報ログイン、パスワードの保存、TLSの傍受
  • MFA、Conditional Access、管理者の同意、無効にされたサービスの回避
  • Graphへの自動切り替えや、Graphを使った機能の探索
  • Teamsのチャット・チャネル機能の正式提供（現在はプレビュー）
  • Teamsの通話、録画、プレゼンス、会議のライフサイクル管理
  • メールの内容を権限や指示として扱うこと
  • モニタリング、エージェントの実行、外部へのデータ送信を初期状態で有効にすること
  • Gmailのメールをすぐに完全削除すること

テストと確認状況

互換性の表記について

開発中の接続方法は、合成データを使った決定的な契約テストで検証しています。実際のプロバイダーで動くと書くには、オプトインで行い、合成データだけを使い、実行したコミットと環境を記録した確認が必要です。

対応済み：公開しているバイナリで使える機能です。

合成契約テスト：プロバイダーの仕様をまねたテストデータで検証したものです。

実環境で確認済み：記録に残したオプトインの実環境確認がある場合だけ使います。

機能の制限：使えない機能があることを隠さずに結果で返すことです。
