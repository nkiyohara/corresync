Corresync가 계정과 데이터를 다루는 방식

로그인은 브라우저와 운영체제 키체인에서 처리하고, 세션과 권한은 계정마다 따로 둡니다. 영향이 큰 원격 쓰기는 미리보기와 일회용 승인을 거쳐야 실행됩니다.

승인 절차 보기개인정보 처리방침
설정 파일에 비밀 정보 없음설정 형식 자체에 비밀번호, 토큰, Cookie, 새로 고침 토큰을 넣을 자리가 없습니다.
계정별 분리계정 ID, 세션, 프로필, 동기화 위치, 캐시, 감사 기록을 계정마다 따로 둡니다.
서버에서 확인하는 승인승인은 미리 본 요청자, 계정, 대상, 내용과 같을 때 한 번만 쓸 수 있습니다.

로그인과 자격 증명

에이전트와 Corresync 본체는 비밀번호를 보관하지 않습니다

브라우저 방식은 화면에 보이는 브라우저에서 로그인하고, 로그인 정보도 거기에 남습니다. 표준 프로토콜의 비밀번호는 동의를 거쳐 운영체제 키체인이나 승인한 자격 증명 도우미에서 읽습니다.

Outlook Web

로그인 정보와 사이트 데이터는 전용 브라우저 프로필에만 두며, 설정, 감사 로그, MCP 출력에 복사하지 않습니다.

OAuth

시스템 브라우저, PKCE, state 검증, 고정된 리디렉션 주소를 사용합니다. Graph는 직접 선택해야 쓰며 자동 대체 경로가 아닙니다.

개방형 표준

유효한 TLS가 필요하고, 설정에는 비밀번호 대신 저장 위치만 기록합니다. 인증이 필요한 탐색은 자동으로 하지 않습니다.

직접 만든 Google OAuth 클라이언트

본인이 만든 데스크톱 OAuth 클라이언트를 씁니다. 검사한 자격 증명과 계정 권한은 서로 다른 키체인 항목에 저장합니다.

쓰기 작업 승인

승인은 미리 본 작업에만 쓸 수 있습니다

서버가 만든 미리보기에는 계정, 서비스, 대상, 내용이 들어 있습니다. 승인 토큰은 요청자, 이 값들, 만료 시각에 암호학적으로 묶이며 다시 쓸 수 없습니다.

  • 계정, 받는 사람, 첨부 파일, 본문이 바뀌면 승인은 거부됩니다.
  • 승인은 금방 만료되고, 한 번 쓰면 없어집니다.
  • 처리됐는지 알 수 없는 원격 쓰기는 자동으로 다시 보내지 않습니다.
  • CLI와 MCP는 같은 정책 검사를 거치므로 우회할 수 없습니다.

메일과 일정 내용

메일과 일정 내용은 데이터로만 다룹니다

메시지, 첨부 파일, 링크, 일정 필드, 가져온 파일, 모니터링 이벤트는 모두 신뢰하지 않는 입력입니다. 이 내용으로 명령 실행, 권한 확대, 로그인, 모니터링 켜기, 외부 전송을 할 수 없습니다.

정해진 도구만 제공

임의 작업이나 범용 속성 API는 없습니다. 입력은 크기와 형식을 제한해 파싱합니다.

로컬 stdio MCP

로컬 프로세스끼리만 통신하며 중계 서버, 원격 MCP 엔드포인트, TLS 가로채기를 쓰지 않습니다.

따로 켜는 기능

가져오기, 모니터링, 에이전트 실행, 외부 전송은 각각 따로 켜며 기본값은 꺼짐입니다. MCP로는 켤 수 없습니다.

메일 내용을 남기지 않는 감사 기록

작업 결과 확인에 필요한 최소 정보만 남기고 주소, 받는 사람, 제목, 본문, 첨부 파일 이름, 비밀 정보는 기록하지 않습니다.

네트워크

탐색은 공개 정보만 보고, 로그인은 사용자가 시작합니다

자격 증명 없는 탐색은 유효한 TLS와 공개 메타데이터만 씁니다. 관리자 동의 화면이나 Graph, Google 권한 요청을 자동으로 띄우지 않습니다.

  • 표준 프로토콜의 리디렉션과 엔드포인트에는 SSRF와 프로토콜 다운그레이드를 막는 규칙을 적용합니다.
  • 웹 지원 여부 확인은 도메인만 고정된 DNS-over-HTTPS 해석기로 조회하고, 그 도메인의 URL은 가져오지 않습니다.
  • 계정 기능은 브랜드로 추측하지 않고 로그인 후 계정마다 확인합니다.
  • 기능 제한, 부분 실패, 알 수 없는 결과를 성공으로 표시하지 않습니다.

사용자가 할 일

로컬에서 실행된다고 해서 자동으로 안전한 것은 아닙니다

  • 신뢰할 수 있는 출처의 릴리스만 설치하고, 기기, 운영체제 계정, 브라우저, 키체인, 백업을 안전하게 관리하세요.
  • MCP 클라이언트는 결과를 원격 모델로 보낼 수 있으니 그 개인정보 처리 조건을 확인하세요.
  • 중요한 작업은 승인하기 전에 계정, 대상, 날짜, 내용을 직접 확인하세요.
  • 조직 정책, MFA, Conditional Access, 관리자 동의, 기존 권한은 그대로 적용됩니다.
  • 보안 취약점은 공개 이슈 대신 비공개 보안 신고로 알려 주세요.
