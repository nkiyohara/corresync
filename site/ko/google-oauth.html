Google OAuth 설정

직접 만든 OAuth 클라이언트로 Google 계정 연결하기

본인이 관리하는 Google Cloud 프로젝트에 ‘데스크톱 앱’ OAuth 클라이언트를 만듭니다. Corresync는 내려받은 파일을 검사해 자격 증명을 OS 키링에 저장합니다. 로그인, MFA, 동의는 평소처럼 Google 화면에서 합니다.

단계별 화면 보기지원 상태 보기
직접 만든 OAuth 클라이언트로 사용할 수 있습니다. Corresync가 관리하는 OAuth는 꺼져 있습니다.

어댑터는 합성 계약 테스트를 통과했지만 현재 버전의 실환경 확인 기록은 없습니다. Google 프로젝트의 대상, 할당량, 경고, 조직 정책은 그대로 적용됩니다.

설정 화면 네 개

필요한 항목만 설정하는 Google 프로젝트

아래 그림은 실제 계정 캡처가 아닌 안내도입니다. Google이 메뉴 이름을 바꿔도 찾아갈 화면과 선택할 항목은 같습니다.

01 · 프로젝트

본인 소유 프로젝트 만들기 또는 선택

Google Cloud Console 위쪽의 프로젝트 선택 메뉴에서 만들거나 고릅니다. 다른 앱의 클라이언트나 자격 증명은 다시 쓰지 마세요.

02 · API

쓸 서비스의 API만 활성화

메일에는 Gmail API, 캘린더와 Meet 링크에는 Google Calendar API를, 할 일을 쓸 때만 Google Tasks API를 활성화합니다.

03 · 대상

대상(Audience)과 범위 선택

조건을 갖춘 Workspace 조직 하나 안에서만 쓸 때는 Internal을, 그 밖에는 External을 고릅니다. Testing 중에는 연결할 계정을 테스트 사용자로 추가하세요. 테스트 승인은 7일 뒤 만료됩니다.

04 · 클라이언트

데스크톱 앱 클라이언트를 만들고 JSON 내려받기

Clients에서 ‘데스크톱 앱’을 고르세요. 웹 애플리케이션, 서비스 계정, API 키가 아닙니다. 내려받은 JSON은 비공개로 두세요.

Corresync로 가져오기

안내 설정으로 클라이언트 가져오기

corr setup을 실행하고 Google과 사용할 서비스를 고른 다음 ‘다운로드한 클라이언트 JSON 가져오기’를 선택합니다. 클라이언트 ID, 루프백 URI, 범위, 분리된 키링 핸들을 확인합니다. 계정 추가 단계에서는 로그인하지 않습니다. 

$ corr setup
$ corr auth login --account personal
$ corr doctor --account personal

스크립트에서는 먼저 corr auth google-client import FILE --key HANDLE을 실행하세요. 자격 증명을 TOML, 명령 인수, MCP, 이슈, 지원 출력에 붙여 넣지 마세요. Corresync는 내려받은 파일을 삭제하지 않습니다.

게시 상태와 Google 정책

개인 용도라면 앱 인증이 필요 없을 수 있지만 제한은 있습니다

Google은 현재 사용자 100명 미만의 개인 용도와 조건을 갖춘 내부 용도를 앱 인증이 필수가 아닌 경우로 안내합니다. 미확인 앱 경고, 사용자 수 제한, 제한 범위 정책, 조직 통제, 최신 약관은 따로 적용됩니다.

  • Testing에서는 등록한 테스트 사용자만 쓸 수 있고 승인은 7일 뒤 만료됩니다.
  • Workspace 관리자는 특정 클라이언트 ID와 범위를 차단하거나 검토 대상으로 지정할 수 있습니다.
  • 정책을 피하려고 서비스 계정, 도메인 전체 위임, 약한 보안 설정을 쓰지 마세요.
  • MCP는 이미 인증된 세션을 쓸 수는 있지만 Google OAuth를 시작할 수는 없습니다.
