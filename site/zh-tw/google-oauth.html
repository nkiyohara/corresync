Google OAuth 設定

不用等 Corresync 的 OAuth 審核，也能連接 Google

在你管理的 Google Cloud 專案中建立「桌面應用程式」OAuth 用戶端。Corresync 會驗證下載檔，把產生的憑證存入作業系統鑰匙圈；登入、MFA 和同意都在平常的 Google 瀏覽器頁面完成。

看圖解設定步驟查看支援狀態
可以使用自備的 OAuth 用戶端；Corresync 代管的 OAuth 目前停用。

介接器已有合成契約測試，但這個版本還沒有實際環境的觀察紀錄。Google 專案的對象、配額、警告和組織政策都照常適用。

設定步驟

在 Google Cloud Console 中的四個步驟

以下是加上標註的頁面示意，不含真實帳號資料。即使 Google 改了選單名稱，要選的項目和注意事項仍相同。

01 · 專案

建立或選擇你擁有的專案

開啟 Google Cloud Console，用頂端的專案選擇器建立或選取專案。不要挪用其他應用程式的用戶端或憑證。

02 · API

只啟用要用的 API

郵件啟用 Gmail API；行事曆與 Meet 會議連結啟用 Google Calendar API；選了工作時才啟用 Google Tasks API。

03 · 對象

選擇對象與權限範圍

只有在同一個符合資格的 Workspace 組織內部使用時才選 Internal，其他情況請選 External。發布狀態為 Testing 時，把要連接的帳號加入測試使用者；測試授權七天後失效。

04 · 用戶端

建立桌面應用程式並下載 JSON

在 Clients 選擇「桌面應用程式」，不要選 Web 應用程式、服務帳戶或 API 金鑰。下載的 JSON 檔請當作私密檔案。

匯入 Corresync

用引導式設定匯入用戶端

執行 corr setup，選擇 Google 和所需服務，再選「匯入已下載的用戶端 JSON」。核對用戶端 ID、回送 URI、權限範圍和分開的鑰匙圈控制代碼。新增帳號本身不會登入。 

$ corr setup
$ corr auth login --account personal
$ corr doctor --account personal

如果要自動化，先執行 corr auth google-client import FILE --key HANDLE。不要把產生的憑證貼到 TOML、指令參數、MCP、Issue 或支援請求中。Corresync 不會自行刪除你提供的下載檔。

發布狀態與限制

個人使用可能不需要審核，但仍有限制

Google 目前將少於 100 名使用者的個人用途和符合資格的內部用途列為不強制驗證。未驗證應用程式警告、人數上限、受限權限範圍政策、組織管控和最新條款仍然適用。

  • Testing 只允許已登記的測試使用者，授權七天後失效。
  • Workspace 管理員可以封鎖確切的用戶端 ID 與權限範圍，或要求審查。
  • 不要用服務帳戶、全網域委派或降低安全性來繞過政策。
  • MCP 可以使用已登入的工作階段，但不能開始 Google OAuth 登入。

建立用戶端後安裝 Corresync
