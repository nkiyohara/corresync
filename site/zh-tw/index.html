本機優先 · MCP 伺服器 + CLI

所有信箱和行事曆，一個本機 MCP 就夠了。

把工作與個人郵件、行事曆連線到 Codex、Claude Code、任何 MCP 智慧體和終端。Corresync 始終隔離每個帳號的身分與授權，同時讓你跨收件匣搜尋、彙總日程，並在任何傳送發生前親自確認。

現已支援：Outlook Web · Microsoft Graph · JMAP · IMAP/SMTP · CalDAV。即將支援：Gmail 和 Google 行事曆，等待 Google OAuth 審核。每個帳號的能力與管理員要求都會明確展示——比較連線方式。

四步完成設定檢查信箱是否支援

登入留在瀏覽器或系統鑰匙圈中，智慧體不會持有由 Corresync 管理的認證資料，也不存在託管中繼。重要寫操作會先顯示準確預覽，只有確認後才會提交。

立即安裝

按系統選擇一條命令，再連線你已經在用的智慧體。

macOS · Linux

curl -LsSf https://corresync.org/install.sh | sh

Windows · PowerShell

powershell -NoProfile -Command "irm https://corresync.org/install.ps1 | iex"

Windows · WinGet

winget install --id nkiyohara.Corresync --exact

下一步 · 新增帳號

corr setup you@example.com --alias personal

請替換示例位址和別名。設定過程只做無認證資料發現，不會自動開啟登入頁面。其他安裝方式和各 MCP 用戶端命令請見開始使用。

一個 MCP，連線每個帳號工作和個人身分始終隔離；每條結果都會保留來源帳號和供應商。
智慧體不接觸認證資料登入由可見瀏覽器或系統鑰匙圈管理，沒有託管中繼或遠端 MCP。
先預覽，再提交傳送和破壞性操作先回傳伺服器強制的審閱；核准短時且僅可使用一次。

Google 支援狀態

程式碼已經就緒，目前只等審核。

Gmail 和 Google 行事曆程式碼已經包含在 RC 中，但正式環境 OAuth 仍然關閉：不會啟動 Google 登入、讀取鑰匙圈、要求 OAuth 權限範圍或傳送 API 請求。通過審核後也必須透過另一次獨立審閱的發布才能啟用。

隱私政策使用條款

安裝後只需三組短命令

選擇。登入。提問。

Corresync 不會預選供應商。它先為位址收集無認證資料證據，新增你明確選擇的帳號路徑，然後才允許啟動該帳號的登入。

1 · 選擇並登入

corr setup you@example.com --alias personal
corr auth login --account personal

發現過程不會開啟任何頁面；單獨的 login 命令只使用已選路徑。

2 · 連線

corr mcp setup codex

在智慧體中註冊本機 stdio 伺服器，重啟用戶端一次即可。

3 · 提問

› 彙總所有帳號裡今天中午前
  需要我處理的事情

智慧體呼叫型別化工具，回答會標明每條資訊來自哪個帳號。

第一天就能完成

一次提問，覆蓋多個收件匣和行事曆。

CLI 與 MCP 共享相同的型別化操作、帳號隔離和策略檢查。

同時搜尋所有收件匣

“找出季度計劃郵件，我忘了它在工作還是個人信箱。” 

$ corr mail search --all-accounts \
    --query 'subject:"quarterly plan"'
● work · microsoft-owa  Ana Ruiz  Plan review
· personal · jmap   Finance      Plan receipt

某個帳號失敗時會明確顯示為部分結果，不會悄悄隱藏。

查看統一日程

“工作和個人行事曆裡的今天安排是什麼？”

$ corr agenda list --all-accounts \
    --start 2026-07-29T00:00:00Z \
    --end 2026-07-30T00:00:00Z
09:30 work      Design review · Teams
12:30 personal  Dentist

時區、行事曆和供應商來源會保留在每個事件上。

傳送前先看清內容

“替我起草給 Ana 的回覆，傳送由我確認。”

  mail_send

確認這份內容之前不會傳送。

看得見的安全設計

第一次呼叫絕不會直接傳送。

重要操作先回傳審閱。核准會繫結呼叫方、帳號、供應商、目標、內容、有效期，並且只能使用一次。

  • 智慧體只拿到型別化工具。密碼、Cookie 和 OAuth 授權 不會出現在 MCP 或設定裡。
  • 只在本機執行。MCP 透過本機 stdio 通訊，沒有託管中繼或遠端端點。
  • 結果不明就停止。不會自動重試狀態不確定的遠端寫入。
  • 郵件內容是不可信資料。它不能授予執行命令或啟動智慧體的權限。

使用你已有的連線方式

需要時用原生 API，可以時優先開放標準。

郵件和行事曆路徑分別選擇，因此一個帳號可以把 IMAP/SMTP 郵件與 CalDAV 行事曆組合起來。

瀏覽器管理

Outlook Web

互動式 Outlook 登入留在專用可見瀏覽器中，同時提供型別化郵件和行事曆操作。

明確 OAuth

Microsoft Graph · Google 即將上線

Graph 使用你有權使用的公開用戶端。Google 路徑在正式環境 OAuth 通過審核前完全關閉。

開放標準

JMAP、IMAP/SMTP、CalDAV

使用加密端點，以及系統鑰匙圈或明確核准的認證資料輔助程式。

證據也說清楚。每條路徑都有確定性的合成契約測試；Google API 路徑目前關閉且尚未進行即時觀測。

限制同樣透明

做不到什麼，也是產品的一部分。

完整能力、限制和證據範圍請見功能頁面。

  • Gmail 和 Google 行事曆仍在等待審核。程式碼在 RC 中，但正式環境 OAuth 保持關閉。
  • Microsoft Graph 需自備 OAuth。Corresync 不營運權杖中繼服務。
  • Windows 桌面通知暫不可用。佇列與已核准的執行器 仍可使用。
  • 支援宣告受證據約束。合成契約不會被包裝成即時相容性證明。
  • 不管理 Teams 聊天或會議生命週期。僅處理行事曆事件上的原生加入連結。
