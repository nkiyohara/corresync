安全說明

AI 代理只能使用工具，拿不到你的憑證

Corresync 只在本機使用你帳號原有的權限。密碼、Cookie 和 OAuth 權杖不會經過 MCP；每次寫入都先確認對象和內容，再送出一次。

查看安全原則資料如何處理

安全原則

六項安全原則

01

憑證存放在固定的位置

瀏覽器登入狀態留在專用瀏覽器中，API 授權和標準協定的機密資訊存放在作業系統鑰匙圈或經你核准的輔助程式。設定檔不儲存機密資訊。

02

每次寫入只針對一個帳號

讀取可以跨帳號；寫入前會用固定的內部識別碼找出確切的一個帳號和資料夾或行事曆。

03

重要操作先預覽

傳送、修改活動、移動和刪除會先回傳由伺服器檢查的預覽；對象或內容不同就無法送出。

04

結果不明時停止

無法確定遠端寫入是否成功時不會自動重試，以免重複傳送或重複修改。

05

預設不監控

匯入掃描是唯讀的。監控、AI 代理派送和資料外傳要分別開啟，預設關閉，MCP 無法開啟。

06

照實顯示限制

登入後才依帳號確認實際能用的功能，不會從品牌推測。功能降級和部分失敗都會回報。

架構

人、指令碼和 AI 代理走同一套檢查

CLI 和 MCP 呼叫相同的應用層功能。服務供應商的介接層只負責轉換協定，不做任何政策判斷。

CLI · MCP→typed application use cases
account · policy · 預覽／送出→服務供應商介接層

預覽與送出

先看預覽，送出時內容必須一致

核准只對同一個呼叫者、帳號、服務、對象、版本、內容和操作有效，有期限，而且只能使用一次。

有時效

過期的預覽不能再拿來送出。

只能用一次

同一個核准不能送出兩次。

只對預覽的內容有效

帳號、收件人或內容有任何變動，就要重新預覽。

CLI 和 MCP 相同

由核心程式執行政策檢查，不依賴 MCP 的 annotation。

登入與憑證

先選連線方式，你要求時才登入

查詢連線方式時不使用憑證，需要有效的 TLS，也不會要求管理員同意。

Outlook Web

互動式登入在專用瀏覽器中進行。密碼和 Cookie 不會進入核心，也不繞過 SSO、MFA 或 Conditional Access。

Google 和 Graph

在系統的預設瀏覽器中用 OAuth 和 PKCE 登入，授權存放在作業系統鑰匙圈。Graph 要你自己選擇才會使用。Google 使用你自己的桌面版 OAuth 用戶端，用戶端憑證存放在另一個鑰匙圈項目。

JMAP、IMAP/SMTP、CalDAV

設定檔只存放憑證的參照，機密資訊透過你同意使用的外部憑證介面讀取。一律需要有效的 TLS，也不做 TLS 攔截。

不可信的資料

郵件內容不能授權任何操作

內文、附件、活動和服務供應商的回應都是不可信資料。其中的文字不能呼叫工具、新增帳號、開始監控或代替核准。

先讀中繼資料

選定郵件之前不讀取內文和附件，每次讀取都有大小上限。

唯讀匯入

不沿用其他應用程式的機密資訊，只列出可匯入的項目。

監控（選用）

你設定好查詢條件、帳號、間隔和通知對象後才會執行。

意見回饋

分享前會先讓你檢查，不包含郵件、位址、權杖或憑證。

不提供的功能

Corresync 不會擴大帳號原有的權限

  • 託管的權杖或郵件中繼服務、多使用者伺服器、遠端 MCP 端點
  • 在 Corresync 設定檔中儲存密碼、應用程式密碼、OAuth 權杖或 Cookie
  • 無人操作的自動登入、TLS 攔截、繞過 MFA 或 Conditional Access
  • 整個租用戶範圍或系統管理員層級的存取
  • 自動改用 Graph，或用 Graph 自動探測
  • Teams 聊天和頻道的正式支援（目前是預覽功能）
  • Teams 通話、錄影、上線狀態監控和會議生命週期管理

測試範圍

合成測試不代表實際服務一定能用

預設測試和 CI 只使用不含憑證和個人資料的合成測試資料。連到實際信箱的測試必須手動開啟，預設的測試指令和 CI 都不會執行。

服務原生功能：依官方文件和合成契約測試驗證。

Live-observed：只有記錄了確切 commit、release、環境和合成資料的觀察紀錄，才能這樣標示。

可用功能：登入後依帳號確認，不從品牌推測。

原始碼

這些限制都寫在文件和測試中
