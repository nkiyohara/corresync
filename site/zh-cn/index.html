本地优先 · MCP 服务器 + CLI

所有邮箱和日历，一个本地 MCP 就够了。

把工作与个人邮件、日历连接到 Codex、Claude Code、任何 MCP 智能体和终端。Corresync 始终隔离每个账号的身份与授权，同时让你跨收件箱搜索、汇总日程，并在任何发送发生前亲自确认。

现已支持：Outlook Web · Microsoft Graph · JMAP · IMAP/SMTP · CalDAV。即将支持：Gmail、Google 日历和 Google Tasks，等待 Google OAuth 审批。每个账号的能力与管理员要求都会明确展示——比较连接方式。

四步完成设置检查邮箱是否支持

登录留在浏览器或系统钥匙串中，智能体不会持有由 Corresync 管理的凭据，也不存在托管中继。重要写操作会先显示准确预览，只有确认后才会提交。

立即安装

按系统选择一条命令，再连接你已经在用的智能体。

macOS · Linux

curl -LsSf https://corresync.org/install.sh | sh

Windows · PowerShell

powershell -NoProfile -Command "irm https://corresync.org/install.ps1 | iex"

Windows · WinGet

winget install --id nkiyohara.Corresync --exact

corr setup

设置会从当前本地状态继续，在不使用凭据的情况下发现账号路径，并在应用前预览账号与智能体配置；登录仍是独立操作。其他安装方式和各 MCP 客户端命令请见快速开始。

一个 MCP，连接每个账号工作和个人身份始终隔离；每条结果都会保留来源账号和提供商。
智能体不接触凭据登录由可见浏览器或系统钥匙串管理，没有托管中继或远程 MCP。
先预览，再提交发送和破坏性操作先返回服务器强制的审阅；批准短时且仅可使用一次。

代码已经就绪，目前只等审批。

Gmail、Google 日历和 Google Tasks 代码已经包含在 RC 中，但生产环境 OAuth 仍然关闭：不会启动 Google 登录、读取钥匙串、申请 OAuth 权限范围 或发送 API 请求。获批后也必须通过另一次独立审阅的发布才能启用。

隐私政策使用条款

安装后只需三组短命令

选择。登录。提问。

Corresync 不会预选提供商。它先为地址收集无凭据证据，添加你明确选择的账号路径，然后才允许启动该账号的登录。

1 · 选择并登录

corr setup you@example.com --alias personal
corr auth login --account personal

发现过程不会打开任何页面；单独的 login 命令只使用已选路径。

2 · 连接

corr mcp setup codex

在智能体中注册本地 stdio 服务器，重启客户端一次即可。

3 · 提问

  需要我处理的事情

智能体调用类型化工具，回答会标明每条信息来自哪个账号。

看得见的安全设计

第一次调用绝不会直接发送。

重要操作先返回审阅。批准会绑定调用方、账号、提供商、目标、内容、有效期，并且只能使用一次。

  • 智能体只拿到类型化工具。密码、Cookie 和 OAuth 授权 不会出现在 MCP 或配置里。
  • 只在本地运行。MCP 通过本机 stdio 通信，没有托管中继或远程端点。
  • 结果不明就停止。不会自动重试状态不确定的远程写入。
  • 邮件内容是不可信数据。它不能授予执行命令或启动智能体的权限。

开放标准

JMAP、IMAP/SMTP、CalDAV

使用加密端点，以及系统钥匙串或明确批准的凭据助手。

证据也说清楚。每条路径都有确定性的合成契约测试；Google API 路径当前关闭且尚未进行实时观测。

限制同样透明

做不到什么，也是产品的一部分。

完整能力、限制和证据范围请见功能页面。

  • Gmail、Google 日历和 Google Tasks 仍在等待审批。代码在 RC 中，但生产环境 OAuth 保持关闭。
  • Microsoft Graph 需自备 OAuth。Corresync 不运营令牌中继服务。
  • Windows 桌面通知暂不可用。队列与已批准 执行器 仍可使用。
  • 支持声明受证据约束。合成契约不会被包装成实时兼容性证明。
  • 不管理 Teams 聊天或会议生命周期。仅处理日历事件上的原生加入链接。
