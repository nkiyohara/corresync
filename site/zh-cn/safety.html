安全模型

智能体只能调用工具，拿不到你的凭据

Corresync 在本机运行，只使用账号已有的权限。密码、Cookie 和 OAuth 令牌不经过 MCP。写入前要确认目标和内容，批准只能用一次。

基本规则

六条基本规则

01

凭据存放的位置

浏览器会话保存在专用的可见浏览器中；API 授权和标准协议凭据保存在系统钥匙串或经你批准的凭据助手中。配置文件不保存机密信息。

02

每次写入只针对一个账号

读取可以跨账号；写入前必须按固定内部 ID 确定唯一的账号和目标文件夹或日历。

03

重要操作先预览

发送、修改事件、移动和删除会先返回预览，由服务器与具体内容绑定。目标或内容不一致就无法执行。

04

结果不明确时停止

远程写入结果不明确时不会自动重试，以免重复发送或重复修改。

05

默认不监控

导入扫描是只读的。监控、智能体调度和数据外发需要分别开启，默认都是关闭的，MCP 无法开启它们。

06

如实报告限制

登录后按账号检查实际功能，不按品牌推断；降级和部分失败都会报告。

架构

人、脚本和智能体走同一套检查

CLI 和 MCP 调用同一组应用层用例。各服务商的适配器只负责协议转换，不包含策略逻辑。

CLI · MCP→typed application use cases
account · policy · 预览／提交→provider adapters

预览和确认

先预览，确认时内容必须一致

批准与调用方、账号、服务商、目标、版本、内容、操作效果和有效期绑定，并且只能使用一次。

有时效

过期的预览不能再使用。

只能用一次

同一个批准不能执行两次。

与目标绑定

账号、收件人或内容有任何改动，都需要重新预览。

CLI 和 MCP 相同

策略由核心代码检查，不依赖 MCP 注解。

登录和认证

先选连接方式，需要时再登录

查找连接方式时不使用凭据，要求有效的 TLS 证书，也不会发起管理员同意流程。

Outlook Web

在专用的可见浏览器中交互登录。密码和 Cookie 不会导入 Corresync 核心，也不会绕过 SSO、MFA 或 Conditional Access。

Google 和 Graph

在系统浏览器中通过 OAuth 和 PKCE 登录，授权保存在系统钥匙串中。Graph 需要你自己选择才会使用。Google 使用你自己的桌面 OAuth 客户端，客户端凭据单独保存在一个钥匙串条目中。

JMAP、IMAP/SMTP、CalDAV

配置文件里只保存凭据的引用，机密信息经你同意后通过外部凭据接口读取。始终要求有效的 TLS 证书，不拦截 TLS。

不可信数据

邮件内容不能授权任何操作

邮件正文、附件、日历事件和服务商响应都是不可信数据，其中的文字不能触发工具调用、添加账号、启动监控或代替你的批准。

先读元数据

选中具体邮件之前不读取正文和附件，所有读取都有大小上限。

只读导入

不复用其他应用的机密信息，只列出可导入的项目。

监控（需开启）

只有设置了查询条件、账号、间隔和通知目标后才会运行。

反馈

发送前由你检查，不包含邮件、地址、令牌或凭据。

不支持

Corresync 不会超出账号已有的权限

  • 令牌或邮件中继服务器、多用户服务器、远程 MCP 端点
  • 在核心配置中保存密码、应用专用密码、OAuth 令牌或 Cookie
  • 无人值守登录、拦截 TLS、绕过 MFA 或 Conditional Access
  • 租户范围的访问或管理员权限
  • 自动改用 Graph，或自动探测 Graph 是否可用
  • Teams 聊天和频道的正式支持（目前是预览功能）
  • Teams 通话、录制、在线状态监视和会议生命周期管理

验证范围

合成测试不代表已在真实服务上验证

默认测试和 CI 只使用不含凭据和个人信息的合成测试数据。连接真实邮箱的测试需要手动开启，默认测试命令和 CI 都不会运行它们。

服务商原生接口：按官方文档和合成契约测试验证。

Live-observed：只有记录了具体提交、版本、运行环境并使用合成数据的观察，才能这样标注。

功能：登录后按账号检查，不根据品牌推测。
