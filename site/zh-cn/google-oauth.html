Google OAuth 设置

用自己的 OAuth 客户端连接 Google，不必等 Corresync 通过 OAuth 审核

在你管理的 Google Cloud 项目中创建“桌面应用”OAuth 客户端。Corresync 检查下载的文件，把生成的凭据存入系统钥匙串。登录、MFA 和授权仍在常用浏览器的 Google 页面中完成。

查看设置步骤查看支持状态
自备 OAuth 客户端已可使用；由 Corresync 管理的 OAuth 未启用。

适配器已通过合成契约测试，尚未实机观察。Google 项目的受众、配额、警告和组织政策仍然适用。

设置步骤

在 Google Cloud Console 中的四个步骤

下面是带标注的示意图，不含真实账号数据。Google 调整菜单名称时，要选择的内容不变。

01 · 项目

创建或选择自己的项目

打开 Google Cloud Console，用顶部的项目选择器新建或选择项目。不要复用其他应用的客户端或凭据。

02 · API

只启用需要的 API

邮件需要 Gmail API；日历和 Meet 会议链接需要 Google Calendar API；只在用到任务时启用 Google Tasks API。

03 · 受众

选择受众和权限范围

只在同一个符合条件的 Workspace 组织内部使用时选 Internal，其他情况选 External。Testing 状态下要把待连接的账号加为测试用户，授权七天后失效。

04 · 客户端

创建桌面应用客户端并下载 JSON

在 Clients 中选择“桌面应用”，不要选 Web 应用、服务账号或 API 密钥。下载的 JSON 要作为私密文件保管。

导入到 Corresync

用引导设置导入客户端

运行 corr setup，选择 Google 和需要的服务，然后选择“导入已下载的客户端 JSON”。核对客户端 ID、回环 URI、权限范围和分开的钥匙串句柄。添加账号不会登录。 

$ corr setup
$ corr auth login --account personal
$ corr doctor --account personal

在脚本中使用时，先运行 corr auth google-client import FILE --key HANDLE。不要把生成的凭据粘贴到 TOML、命令参数、MCP、Issue 或求助信息中。Corresync 不会自动删除你下载的文件。

发布状态

个人使用可能不需要验证，但仍有限制

Google 目前把少于 100 名用户的个人用途和符合条件的内部用途列为不强制验证的情况。未验证应用的警告、用户数上限、受限权限范围政策、组织管控和 Google 当前的条款依然适用。

  • Testing 状态下只有登记过的测试用户能授权，授权七天后失效。
  • Workspace 管理员可以阻止具体的客户端 ID 和权限范围，或要求审核。
  • 不要通过服务账号、全网域委派或降低安全设置来绕过政策。
  • MCP 可以使用已登录的会话，但不能发起 Google OAuth。
