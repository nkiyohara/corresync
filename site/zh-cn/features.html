四步开始检查支持服务

日常通信

统一处理邮件和日历，不合并身份。

01

邮件

  • 文件夹、标签与能力发现
  • 有上限的列表、搜索与 thread 搜索
  • 按需读取 header、正文和有上限的附件
  • 创建和更新草稿、回复、转发与发送
  • 已读/未读、归档、移动与垃圾箱
  • 跨账号搜索与明确的部分失败

发送、移动和删除先返回审阅，只有完全一致的内容才能提交一次。

02

日历与日程

  • 明确选择可用日历
  • 有上限的事件列表与跨账号日程
  • 保留时区和重复规则
  • 创建、更新与取消事件
  • 路径报告支持时才请求 Teams 或 Google Meet
  • 会议链接仅作为单个事件的属性

Teams 聊天、频道、通话、录制与会议生命周期管理不在范围内。

同一核心，两种入口

AI 智能体与脚本遵守同一安全边界。

03

AI 智能体 · 本地 stdio

  • 只提供狭窄、类型化的邮件和日历工具
  • 不暴露凭据、Cookie、任意 action 或通用 property API
  • 读取与写入预览/提交明确分开
  • 结果保留账号和提供商来源
  • 不创建 远程 MCP 端点
corr mcp setup codex

04

脚本 · 稳定 JSON

  • 人类输出与机器 JSON 分离
  • 使用同一账号选择和策略检查
  • 不隐藏部分失败、降级或未知结果
  • stdout 输出数据，stderr 输出诊断
  • schema 遵循公开版本策略
corr agenda list --all-accounts --format json

主动开启的本地能力

只在需要时，由你亲自打开。

只读导入暂存

扫描其他应用设置并显示候选，不复用 机密信息，不添加账号，也不认证。

选择性监控

默认关闭。只有明确设置账号、查询、间隔和目标后才在本地运行；MCP 无法启用。

隐私保护反馈

绝不自动发送。字段先供你审阅，且不包含邮件内容、地址、令牌 或凭据。

已验证更新

校验签名 校验和 与 来源证明；包管理器安装仍由对应管理器更新。

安装前常见问题

先把重要问题说清楚。

我的账号能用吗？

支持 Outlook Web、明确配置的 Graph、JMAP、IMAP/SMTP 和 CalDAV。Google 路径已实现但等待生产环境 OAuth 审批。可只用域名检查。

需要付费吗？

Corresync 是 Apache-2.0 开源软件；提供商、云、智能体和网络费用遵循各自条款。

邮件存在哪里？

数据从设备直接连接提供商，没有 Corresync 托管邮箱或令牌 中继服务。本地缓存和游标按账号隔离。

AI 能自行发送吗？

不能。第一次调用只返回审阅，提交需要与内容绑定、短时、单次的批准。

会偷偷联网吗？

没有 analytics 或 telemetry。只有目的明确的可选 兼容性检查工具、更新检查、所选提供商操作与反馈。

发送中途结果不明怎么办？

不会自动重试；会停在“结果未知”，要求核对，避免重复发送。

明确不做

不以便利为名扩大权限。

  • 托管中继服务、多用户服务器、远程 MCP 传输
  • 无人值守登录、保存密码、TLS 拦截
  • 绕过 MFA、Conditional Access、管理员同意或禁用服务
  • 自动 备用路径 到 Graph 或自动能力探测
  • Teams 聊天、频道、通话、录制和会议生命周期管理
  • 把邮件内容当成授权或指令
  • 默认开启监控、智能体派发或数据外传
  • Gmail 即时永久删除

兼容性证据

合成测试不等于实时提供商验证。

开发路径使用确定性的合成 fixture contract。只有记录了 opt-in、合成数据、确切 提交 与环境的观测，才会标记为 live-observed。

supported：已发布 可执行文件 中可用。

synthetic contract：使用模拟 provider contract 的 fixture 验证。

live-observed：存在明确记录的可选实时观测。

degraded：能力缺失会被如实返回。
