邮件和日历

在多个账号间处理邮件和日历

01

邮件

  • 文件夹、标签和功能查询
  • 有上限的列表、搜索和会话搜索
  • 按需读取邮件头、正文和有上限的附件
  • 创建和更新草稿，回复、转发和发送
  • 已读/未读、归档、移动和移入垃圾箱
  • 跨账号搜索；某个账号失败时标为部分结果

发送、移动和删除先返回预览，只有完全一致的内容才能执行一次。

02

日历和日程

  • 选择要用的日历
  • 有上限的事件列表和跨账号日程
  • 保留时区和重复规则
  • 创建、更新和取消事件
  • 连接方式支持时才请求 Teams 或 Google Meet 链接
  • 会议链接只作为单个事件的属性

Teams 聊天和频道目前是预览功能，可以在设置中选择，但实机验证还不完整。通话、录制、在线状态监视和会议生命周期管理不在范围内。

智能体和脚本

AI 智能体和脚本使用同一套规则

03

AI 智能体 · 本地 stdio

  • 只提供用途单一的邮件和日历工具
  • 不提供凭据、Cookie、任意操作或通用属性 API
  • 读取和写入分开；写入要先预览再确认
  • 结果注明来自哪个账号和服务商
  • 不创建远程 MCP 端点
corr mcp setup codex

04

脚本 · JSON 输出

  • 人读输出和机读 JSON 分开
  • 账号选择和策略检查与 MCP 相同
  • 部分失败、降级和未知结果都会输出
  • 数据写 stdout，诊断写 stderr
  • schema 按公开的版本策略变更
corr agenda list --all-accounts --format json

可选的本地功能

需要手动开启的功能

只读导入

扫描其他应用的设置并列出候选项，不复用机密信息，不添加账号，也不登录。

监控（需开启）

默认关闭。设置账号、查询条件、间隔和目标后才在本地运行；MCP 无法开启。

反馈

不会自动发送。发送前可检查每个字段，不含邮件内容、地址、令牌或凭据。

更新校验

校验签名、校验和与来源证明；包管理器安装的仍由包管理器更新。

常见问题

安装前常见问题

我的账号能用吗？

支持 Outlook Web、自行配置的 Graph、Todoist、TickTick、JMAP、IMAP/SMTP 和 CalDAV。Google 使用你自己 Google Cloud 项目中的桌面 OAuth 客户端。可只用域名检查是否支持。

需要付费吗？

Corresync 是 Apache-2.0 开源软件。服务商、云、智能体和网络费用按各自条款收取。

邮件存在哪里？

本机直接连接服务商，Corresync 不托管邮箱，也没有令牌中继。本地缓存和游标按账号分开。

AI 能自己发送邮件吗？

不能。第一次调用只返回预览；执行需要与内容绑定、有时效、只能用一次的批准。

Corresync 会自己联网吗？

没有统计分析或遥测。只在这些情况下联网：可选的兼容性检查、更新检查、你选择的服务商操作和反馈。

发送结果不明确时怎么办？

不会自动重试，而是停在“结果未知”，由你核对，避免重复发送。

不支持

Corresync 不做的事

  • 中继服务器、多用户服务器、远程 MCP 传输
  • 无人值守登录、保存密码、拦截 TLS
  • 绕过 MFA、Conditional Access、管理员同意或已禁用的服务
  • 自动改用 Graph，或自动探测 Graph 是否可用
  • Teams 聊天和频道的正式支持（目前是预览功能）
  • Teams 通话、录制、在线状态监视和会议生命周期管理
  • 把邮件内容当作授权或指令执行
  • 默认开启监控、智能体调度或数据外发
  • Gmail 直接永久删除

验证状态

合成测试与真实账号验证的区别

开发中的连接方式用固定的合成数据做契约测试。只有主动开启、使用合成数据、并记录了具体提交和运行环境的观察，才会标为 live-observed。

supported：已发布的程序中可以使用。

synthetic contract：用模拟服务商接口的测试数据验证。

live-observed：有记录在案、主动开启的实机观察。

degraded：缺少的功能会直接报告出来。
